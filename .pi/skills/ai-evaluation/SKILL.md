# AI 评测（ai-evaluation）

「AI 测试」不是一个动作，是两个阵营、七层对象的混称。先定义对象，再选工具；不要凭「测试」二字直接选某个工具。

## 一、动手前先写清四件事

1. **测的对象**：裸模型、输出内容、Agent 过程、还是线上表现。
2. **什么算失败**：给出可观察的失败形态，不能只写「效果不好」。
3. **判分单位**：唯一答案、按事实点评分、还是多档 rubric。
4. **失败后的动作**：打回改提示词、改模型、还是重新评估方案。

四件事写不出来，说明需求还没明确，先追问，不跑评测。

## 二、七层定位

| 层 | 测什么 | 判据 |
|---|---|---|
| L1 模型能力 | 公开题集上的裸模型得分 | 「这个模型行不行」，与具体产品无关 |
| L2 评测方法与基础设施 | 分数可信度：污染、饱和、口径 | 「这个分数能不能信」 |
| L3 系统工程 | 组件、集成、E2E、成本延迟 | 「系统跑不跑得通」 |
| L4 Agent 与流程 | 任务成功率、工具选择、参数、错误恢复、轨迹 | 「过程做得对不对」 |
| L5 内容输出 | 格式、事实性、幻觉、语气、术语、指令遵循 | 「说出来的话合不合格」 |
| L6 在线生产 | 影子、灰度、A/B、漂移、人机回退率 | 「上线后有没有变坏」 |
| L7 组织流程 | eval 驱动开发、红队、golden set、版本管理 | 「怎么把前六层持续跑起来」 |

L1–L2 为模型评测阵营（离线、公开、可复现）；L3–L6 为业务评测阵营（场景化、私有数据）；L7 是机制。

## 三、工具选择（每层的候选）

| 需求 | 候选工具 | 形态 |
|---|---|---|
| L1 公开基准跑分 | lm-evaluation-harness；批量编排用 OpenCompass 或 HELM | CLI / Python |
| L2 污染检查 | Giskard 或各 harness 的 contamination 报告 | Python |
| L3 语义断言、挂 CI | DeepEval（挂 pytest） | Python |
| L4 Agent 多步过程 | DeepEval agent 指标或 Inspect | Python |
| L4 RAG 组件 | Ragas | Python |
| L5 内容输出（声明式批量） | promptfoo | YAML + CLI |
| L5 开放语义判分 | promptfoo 模型裁判或 DeepEval G-Eval | YAML / Python |
| L6 漂移重跑 | promptfoo 同配置同回归题定期重跑 | CLI + 定时任务 |
| L6 线上轨迹上报（有服务端时） | Langfuse 或 Arize Phoenix | 服务 + SDK |
| L7 红队对抗 | promptfoo redteam | CLI |

同一需求多个工具可做：跟随项目现有技术栈（已用 pytest 选 DeepEval，已有声明式配置选 promptfoo），不为单一工具引入新语言。无服务端条件下，L6 用定期重跑实现，不建观测平台。

## 四、判分口径（按答案确定性分三档）

1. 有唯一答案 → 硬规则：等于/包含/正则/JSON 字段。
2. 有明确对错但表述开放 → 事先列必命中的事实点和不许出现的错误，按点给分。
3. 无标准答案 → 事先写死多档 rubric，或模型交叉评。

语义判分的客观性是行业未解难题：判据必须先于跑批写死；裁判模型与被测模型不同源；结果保留人工抽检。漂移检测须用长期不变的回归题，定义为「同批题、同判分、不同时间点」的通过率变化。

## 五、分数可信度检查

引用任何分数前检查四项：**数据污染、基准饱和、对提示词/判分的敏感性、采样预算口径**。报分数同时报出题日期、判分口径（shot 数、pass@k/cons@k）和已知警示。benchmark 只回答「同类题上的相对位置」，不回答「能不能上线」。

## 六、执行与固化规则

1. 先向需求方说明：测的是哪一层、用哪个工具、为什么。
2. 工具未安装或调用失败时如实说明，不编造结果。
3. 阈值与判据由需求方拍板，不替其放行。
4. 每次实际调用在工作目录的调用登记中记录：日期、层、需求、工具、结果能否直接用、别扭点（模板见 `调用登记.md`）。
5. 同一需求同路径走过两次以上且验证可用 → 固化为默认流程；现有工具确认满足不了 → 按学习文档中的自建路线启动自建模块。

## 深入资料

本技能只给方法和选择口径。各测评的题库来历与有效性分析、各工具的源码结构、许可证与复刻范围，见仓库 `学习文档/ai-evaluation/`（《测评内容调研》《测评工具拆解分析》）。
