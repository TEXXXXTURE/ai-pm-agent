# 干系人沟通话术技能（stakeholder-comms）

起草 PM 最怕发的那类消息。所有难消息共用同一条脊柱：**先说消息（news），再讲推理（reasoning），保住关系与对方诉求中合理的部分（what survives），最后把下一步（next step）说具体**。永远不要把结论埋在最后。

语气原则：直接、不卑不亢；不甩锅给个人或团队、不写"由于带宽/优先级"这类企业烟雾话；该硬的地方不绕，该留的关系不留成假承诺。

## 一、何时使用 / 先问用户什么

### 适用场景
- 用户说"这个需求我想拒绝，怎么说？""怎么跟老板/销售/客户讲""延期通知怎么写""这事我推不动，要升级""老板坚持要做 X，我不认同，怎么回""帮我把这个坏消息传达出去"。
- 典型难场景四类：**拒绝需求**（对功能请求说不）、**宣布延期 / 砍范围**、**向上升级阻塞**（escalation）、**对上推回**（push back on executive）；也适用于传达不受欢迎的调研/数据结论。

### 不适用
- 日常状态同步、常规通知——没有"难消息"不需要本技能的话术骨架。
- 用户其实没想好立场（自己也不知道该拒绝还是接受）——先帮用户理清决策本身（可用优先级/路线图等技能），立场定了再写话术；话术不能替用户做决定。

### 先问用户什么（最多 3 个问题，信息不足先澄清）
1. **受众是谁、对方在乎什么？**——同一个"不"，对护着单子的销售负责人和护着质量的工程师，读法完全不同。还要弄清双方关系与对方的权力位置（对方能否强推、你是否需要对方配合）。
2. **你的真实立场是哪一种？**——是"坚决不"、"现在不"（可谈）、谈判中，还是"决定已做、仅需通知"？消息绝不能把已关闭的决定假装开放（最残忍的失败模式：让对方以为还有机会），也不能把还开放的事假装已定。
3. **用什么媒介发？**——即时消息（Slack/钉钉/飞书）、邮件，还是当面/会议的谈话要点？长度和正式度按媒介匹配。

规则：用户指令里已给出的信息直接采用、不重复问；**3 个问题问完或用户不回应，就带着【假设】标签继续起草，并在话术稿开头标注所采用的假设**（受众、立场、媒介）。

## 二、工作流步骤

1. **识别场景模式，确认真实立场**（坚决/可谈/已关闭）。四类模式各有话术结构，见下。
2. **用用户的口吻起草，按媒介定长度。**默认从短写起——难消息会因为焦虑而灌水（堆铺垫、堆道歉、堆客套），一律砍掉。
3. **剔除模糊消息的对冲词**（"只是""有点""我们可能在考虑"），但**保留服务于关系的软化句**（"我知道这对 XX 客户那单打击很大"）。前者让结论变糊，后者让对方感到被看见。
4. **以收件人的视角重读一遍**：对方看到后的第一句反问会是什么？把这个反问的答案以 P.S. 或备注形式附上，或提前帮用户准备好应答口径。
5. **媒介不确定时，同时给两个版本**：2 行短版（即时消息/口头开场）+ 完整版（邮件/正式通知）。

### 四类话术模式（骨架均为 news → reasoning → what survives → next step）

**A. 拒绝需求（对请求说不）：**
1. 决定放在第一句，不加对冲："这个季度我们不做 X。"
2. 真实理由，简短——讲取舍，不讲企业烟雾话："做它会挤掉 Y，而 Y 服务的客户数是它的 10 倍。"
3. 承认对方诉求中合理的部分——大多数请求里都有一个真问题，只是提出的解法不对；把那个真问题点名出来。
4. 给出你**能**提供的东西：临时绕行方案（workaround）、重新评估的触发条件（"如果再有两家大客户提这个"）、或"什么情况下答案会改变"的明确标准。
5. 门是对关系留的，不是对决定留的。

**B. 宣布延期 / 砍范围：**
1. 消息连同新日期/新范围放第一句。不要用"同步一下时间线哦 :)"开场。
2. 原因诚实讲，不指责个人、不甩锅给团队。
3. 你在做什么防止复发（或者诚实承认"这次是估算失误"）。
4. 对**这位收件人本人**的具体影响，以及你需要他做什么。
5. 绝不宣布一个你自己都不信的新日期——第二次跳票的代价是第一次的 10 倍。

**C. 向上升级阻塞（escalation）：**
1. 框定为"决策请求"而非抱怨："我需要在 [日期] 前在 A 和 B 之间得到一个决策。"
2. 一段话背景——被升级的人没参加过那些会。
3. 两个（最多三个）选项，各带代价，附上你的推荐。
4. 写明默认后果：如果到期没有决策，会发生什么。
5. 确认被"绕过去"的那个人已经先看过这套说法、或知道升级要来；不确定就问用户——突袭式升级烧桥。

**D. 对上推回（push back on executive）：**
1. 先把对方的立场按最强版本复述出来（steel-man）——证明你理解了战略意图。
2. 呈上对方可能没有的数据或约束——是**新信息**，不是把自己的偏好再吵一遍。
3. 确实存在中间路线时才给；不要编造假妥协。
4. 以承诺收尾："如果知道这些之后您仍然要做 X，我们会把它执行好。"——"不同意但承诺"（disagree-and-commit）当面讲清，而不是事后被榨出来。

## 三、markdown 输出模板（话术稿）

```markdown
# 话术稿 — [场景一句话，如"拒绝销售团队的 XX 定制需求"]
**受众**：[谁，他在乎什么] · **媒介**：[即时消息 / 邮件 / 当面谈话要点]
**我的立场**：[坚决不 / 现在不（可谈）/ 谈判中 / 已定仅通知]
**假设**：[用户未回答而采用的假设；没有则写"无"]
**要达成的效果**：[这次沟通后对方应知道什么、做什么]

## 话术正文（可直接发送）
[第一句即消息/结论，不加对冲]
[真实理由：讲取舍，不甩锅、不套话]
[承认对方诉求中合理的部分 / 对对方的具体影响]
[能提供的绕行方案、重估触发条件、或需要对方做的事——下一步具体到人、时间、动作]

## 对方的第一句反问 & 应答口径
- 反问：[最可能被追问的问题] → 应答：[一句话口径]

## 短版（2 行，用于即时消息或口头开场）
[两句以内：结论 + 下一步]
```

落盘建议：话术稿可保存为 `output/话术-<场景>-<日期>.md`。需要做成汇报材料/演示时，按项目规矩产出《演示需求交接单》，不自制 HTML/PPT。
话术涉及的数据、日期、客户名必须用真实信息——没有的数据让用户提供，**绝不编造**。

## 四、呈现前质量自检清单

- [ ] **消息在第一句**。如果第一句也能用来开场一条好消息，重写。
- [ ] **决定的开放程度被诚实表达**——没有假征求意见（已定却装商量），也没有假终局（可谈却装铁板）。
- [ ] **给出了真实理由**："带宽""优先级"是烟雾话；真正的取舍（挤掉了什么、为什么）才是尊重。
- [ ] **有建设性的东西活下来了**：绕行方案、重估触发条件、或改变答案的明确标准，三者至少有一。
- [ ] **无甩锅洗白**：归因到系统和取舍，不点名个人、不写"研发那边"。
- [ ] **预判了对方的第一句反问**，并附了应答口径。
- [ ] 关系软化句保留、模糊对冲词已剔除；长度匹配媒介，难消息没有被焦虑灌水。
- [ ] 升级类话术已确认被绕过方知情；延期类话术的新日期是自己真信的。
- [ ] 产物为 markdown；涉及的事实/数据均为真实信息，未编造。
