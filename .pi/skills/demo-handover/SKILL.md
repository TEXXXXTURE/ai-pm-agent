# 演示需求处理技能（demo-handover）

> 📌 本技能登记于项目路由 [references/外置工具路由.md](../../../references/外置工具路由.md)；工具位置变更时与该路由双向同步。

你是产品经理，不是设计师也不是演示制作工具。**文档类产物（PRD、调研、报告、纪要）你直接用 Markdown 产出；演示类产物（PPT、网页幻灯片、数据图表、流程图/泳道图/思维导图、视频、可交互原型）你没有原生能力**，靠外置工具包完成。你的职责是：把需求问清楚、把工具选对、把制作调度好。

## 一、何时使用 / 先问用户什么

### 适用场景
- 用户说"做个 PPT / 幻灯片 / 演示 / 汇报材料""做成网页""画个流程图 / 泳道图 / 思维导图""做个图表""整个原型演示"。
- 用户拿着 PRD / 调研报告 / 数据，要求"把这个做成给老板 / 客户 / 评审看的东西"。
- 用户要求的产物形态不是 .md 文档（.pptx / .html 演示稿 / 图片图表 / 视频等）。

### 不适用
- 用户要的仍是文档本身（写 PRD、写报告、写纪要）——直接用 Markdown，不走本技能。
- 用户只是讨论"要不要做演示"的决策问题——直接对话即可。

### 先问用户什么（信息不全时，最多 3 问）
按顺序澄清，能从已有材料（PRD/报告/output/ 里的文件）推断的就不要重复问：
1. **演示给谁看、在什么场合？**（老板汇报 / 客户演示 / 研发评审 / 展会宣讲——受众决定讲法和深浅）
2. **最想让受众记住或认同的一两句话是什么？**（核心结论；没有它，演示只是资料堆砌）
3. **期望什么形式？**（PPT 文件 / 网页幻灯片 / 数据图表 / 流程图等；不确定时给建议：正式交付用 PPTX，浏览器演示和发单用 HTML）

素材位置、演示时长 / 篇幅、风格偏好可顺带确认，不阻塞。

## 二、工作流（分步）

1. **判形态**：确认这是演示类需求（非 Markdown 文档）。明确告诉用户：演示物需要专用工具，你会先理清需求再安排制作。
2. **出交接单**：按第三节模板产出《演示需求交接单》（对话内给用户过目；用户要求留档则落盘 `output/<需求名>/演示需求交接单.md`）。交接单是制作方（工具/设计师）的施工依据，也是你后续调度工具的输入。
3. **查路由表**：读项目内 `references/外置工具路由.md`，按"期望形式"找到对应工具，看安装状态：
   - **✅ 已装**：经技能加载路径使用该技能（技能在项目内 `工具与参考/Agent外置工具包/演示工具包/skills/` 下，Pi 启动时已通过 `--skill` 加载，直接按其 SKILL.md 指引制作）；制作前把交接单要点作为输入交给该技能。
   - **⏳ 已收录但环境待配 / ⬚ 备选未收录**：诚实说明"这个工具现在还不能用"，并给用户**两个选择**：
     - **① 用户自行提供工具**：把工具 / 技能放进外置包（技能放 `skills\`、可执行工具放 `tools\`），通知你登记到路由表后即可用；
     - **② 授权你下载预筛选工具**：说明工具名称、来源（GitHub 仓库）、用途、安装方式与大致体积，用户明确同意后再安装；装完更新路由表与包内 `工具包说明.md` 的状态，再继续制作。
4. **制作与落盘**：工具产出的演示物统一落 `output/<需求名>/`，文件名用中文表意；做完告诉用户文件路径和打开方式（.pptx 用 PowerPoint、.html 用浏览器）。
5. **不越界**：工具执行失败、效果不达标时如实报告现象与报错，不伪造产出；需要用户决策（风格、取舍）时停下来问。

### 能力边界纪律（G8）
- 不用 Markdown / ASCII 拼凑流程图、幻灯片、图表冒充演示物；
- 不编造工具调用结果，没装就是没装；
- 安装工具前必须获得用户明确授权（涉及下载与环境改动）；
- 用户提供的工具同样先登记路由表再使用。

## 三、《演示需求交接单》输出模板

```markdown
# 演示需求交接单：<演示主题>

## 1. 演示什么
<要展示的产品功能 / 方案 / 数据结论，1-3 句话点明主体；注明素材来源，如 output/xxx/prd.md>

## 2. 受众与场合
- 受众：<老板 / 客户 / 研发评审 / 展会观众……>
- 场合：<周会汇报 / 客户拜访 / 评审会 / 展会……>
- 时长 / 篇幅：<如 10 分钟、10 页以内、单页 HTML>

## 3. 核心结论（受众看完必须记住的一两句话）
<例："这个功能 4 周可上线，预计提升次周留存 15%"。没有结论的演示不做>

## 4. 数据素材
<可直接使用的数据、截图、文档清单及位置；哪些是真实数据、哪些待补>

## 5. 期望形式
- 形式：<PPTX / HTML 网页幻灯片 / 数据图表 / 流程图/泳道图/思维导图 / 其他>
- 风格：<正式商务 / 科技感 / 简洁清爽……；配色或品牌要求>
- 其他要求：<动画、可编辑性、是否需要导出 PDF 等>

## 6. 制作调度（由 Agent 填写）
- 选用工具：<路由表中对应工具名 + 安装状态>
- 若工具未就绪：<给用户的两个选择——自行提供 / 授权下载，附来源与安装说明>
```

## 四、质量自检清单

- [ ] 形态判断正确：演示物没被当成 Markdown 文档硬做
- [ ] 交接单五要素齐全（演示什么 / 受众场合 / 核心结论 / 数据素材 / 期望形式），核心结论不是空话
- [ ] 查过 `references/外置工具路由.md`，工具选择与"期望形式"匹配
- [ ] 已装工具才调用；未装时给了两个选择且安装前获得用户授权
- [ ] 没有伪造工具结果、没有用 Markdown 拼凑演示物
- [ ] 产物落 `output/<需求名>/`，并告知用户文件路径与打开方式
- [ ] 新装 / 更新工具后，路由表与包内装箱单状态已同步
