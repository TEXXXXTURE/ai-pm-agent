# 模型选型技能（model-selection）

选型问题的答案不在你的记忆里——模型迭代快，凭记忆答规格和价格必然过时。**一律读项目内对照表 + 实时查价，再回答。**

## 一、内容在哪（只指路，不复制）

| 内容 | 位置 | 说明 |
|---|---|---|
| 候选对照表（主料件） | `references/模型候选清单.md` | 国内外模型逐行清单：上下文/最大输出、函数调用/流式、适合的产品形态、已知限制与坑、核对日期与出处。**价格不在此表** |
| 不变字段复核工具 | `scripts/model_catalog.py` | 读 litellm 本地模型表，零网络、零模型调用。用法：`providers` 列 provider 与条目计数、`models <id...>` 输出对照行、`search <关键词>` 找型号 |
| **实时价格** | `scripts/model_catalog.py price <模型 id>` | **问价格只走这条**。优先拉 litellm 官方远端表（实时），远端不可达则自动回退本地备份，并在输出里标注「用的是本地备份，可能已过期」 |
| 权威来源 | litellm 表 `model_prices_and_context_window_backup.json`（路径见脚本文件头） | 上下文窗口、输出上限只认它；价格认远端表（实时）与它的本地副本；与外部说法冲突时以表为准 |

本技能**不复制清单内容**，避免两处维护。清单更新了，技能不用改。

## 二、门槛口径（一句话）

问**价格** → 跑 `scripts/model_catalog.py price <模型 id>` 实时取数，**不引用清单里的历史数字、不凭记忆报数**，报价时说明取数来源与取数时间；问**上下文 / 能力 / 适合什么产品形态** → 读 `references/模型候选清单.md`。

## 三、何时使用

### 适用
- 「这个需求该选哪个模型」「A 模型和 B 模型怎么选」「有没有更便宜的方案」。
- 「X 模型上下文多大 / 多少钱 / 支不支持函数调用 / 支不支持流式」。
- 「长上下文场景用哪个」「要高并发低成本选哪个」「中文长文写作用哪个」。
- 判断某模型能不能承担某个产品形态的需求（如"用 deepseek-chat 写 2 万字 PRD 行不行"）。

### 不适用（走别的入口）
- **AI 领域概念与原理**（ReAct、RAG 机制、Agent 架构）→ `domain-kb-query` 技能查领域知识库。
- **库外最新动态**（昨天刚发布的模型、表内还没收录的型号）→ 联网调研，并明确告诉用户清单的核对日期。价目调整由 `price` 实时取数覆盖，不必联网。
- **第 6 段流水线内的模型横跑选型**（Promptfoo 实测对比）→ 那是流水线节点的事，本技能只做人读的建议，不跑评测、不冒充实测。
- **要写代码接入模型** → 这不是产品经理的活，只给候选与坑，实现交给研发。

## 四、怎么回答（工作流）

1. **读清单**：打开 `references/模型候选清单.md`，**整份读**（对照类信息不能靠检索片段拼，会丢可比性）。先看头部「硬字段的来源与口径」，再看对应章节（国外/国内/嵌入）。
2. **取行**：从表里取相关行，不要凭记忆补规格。表里没有的厂商或型号，就说"清单未收录，需另行核实"——**不要编造规格和价格**。
3. **分两条复核**：用户要确认不变字段时，跑脚本读本地表：
   ```bash
   bash scripts/run-tool.sh scripts/model_catalog.py models deepseek-chat deepseek-reasoner
   ```
   **用户问价格（或你要在回答里报价格）时，跑实时查价，不要用清单或记忆里的历史数字**：
   ```bash
   bash scripts/run-tool.sh scripts/model_catalog.py price deepseek-chat
   ```
   报价时把脚本输出的「取数来源」与「取数时间」一并转述给用户。脚本输出与清单不一致时，以脚本（＝litellm 表）为准，并提醒用户清单需要更新。
4. **转述成人话**：给结论先于细节。按用户的实际约束组织回答（上下文够不够、单价量级、能不能一次写完、有什么坑），不要把表格原样贴给用户。**表格范围小时可整段引用清单行，但要带上核对日期与出处。**
5. **区分清单事实与你的判断**：清单的硬字段是表内数据，直接陈述；「适合的产品形态」列是判断，转述时要说明这是建议。超出清单的补充判断，显式标"这是我的推断，清单未覆盖"。
6. **给出建议但不替用户定**：列 2–3 个候选、各自的取舍（价格/上下文/输出上限/已知坑），把决定权交回用户。**候选只作建议，最终选择由人拍板。**

## 五、回答纪律

1. **数字必带出处与日期**：引上下文时必须带"出处 litellm 表 + 核对日期"；**引价格必须带"取数来源（远端实时 / 本地备份）+ 取数时间"**，不带出处或时间的数字不要给。
2. **价格一律实时取**：不在回答里写"当前价格是……"这类不带时间的说法。远端不可达时脚本会回退本地备份，此时必须把「用的是本地备份，可能已过期」这句一并告诉用户，并建议恢复网络后重跑。
3. **人民币价要现场折算并说明汇率**：脚本只给美元原值（美元/百万 token）。用户要人民币时按当日实时汇率现场折算，说明汇率取值日期与来源，并提醒以厂商账单为准。
4. **不编造实测与榜单**：不给 benchmark 分数、不给"实测更快/更强"这类没出处的说法，不编造模型横跑结论。清单里标「未核实」的项，转述时保留这个标注。
5. **缺价就是缺价**：脚本打出「缺价」提示（表内无 input/output 单价）的型号，如实说"表内无报价，需向厂商核实"，不要用同类模型的价格替它估算。
6. **时效提醒**：清单核对日期较早时（或用户问的是近期动态），先说明清单的核对日期，再回答；必要时建议用户重新核对或走联网调研。
7. **零模型调用**：本技能不调任何模型，只读本地文件与本地 json，价格子命令只拉一张公开 json 表；没有时段限制。

## 六、回答前自检

- [ ] 读了 `references/模型候选清单.md`，没有凭记忆答上下文与能力
- [ ] **价格是跑 `price` 子命令取的实时值**，不是清单里的历史数字，也不是记忆里的旧价
- [ ] 报价带了「取数来源 + 取数时间」；回退本地备份时说明了「可能已过期」
- [ ] 不变字段引用了 litellm 表口径，且带了核对日期与出处
- [ ] 清单未收录的厂商/型号，如实说"未收录、需另行核实"，没有编造
- [ ] 没有编造实测数字、榜单名次、benchmark 分数或横跑结论
- [ ] 区分了清单事实与自己的判断，判断已标注为建议/推断
- [ ] 给了候选的取舍，明确"最终选择由人拍板"，没有替用户定
- [ ] 报人民币时说明了汇率日期与来源，并提醒以厂商账单为准
