# 产品数据分析技能（product-analytics）

拿到用户行为数据后，回答「用户在产品里做了什么、发生了什么变化」，并把结果写成能直接用的分析报告。定义指标和埋点用 metrics-tree 技能，验证因果用实验，本技能只管中间这段：取数、计算、判断、报告。

## 一、何时使用 / 不适用

**适用**
- 用户说「分析一下这批数据 / 漏斗哪步流失多 / 留存怎么样 / 上线后数据有没有变化 / 为什么这周指标跌了 / 出一份数据周报」。
- 手上已有事件级数据（导出文件、数据库表、SQL 查询结果）。

**不适用**
- 还没有定义要衡量什么 → 先用 metrics-tree。
- 要证明「哪个方案更好」且可以做随机分流 → 用实验设计技能。
- 探索期、用户极少、想了解用户为什么这么想 → 先做定性调研，数据量太小时算出来的是噪声。

## 二、动手前确认三件事

1. **指标口径**：每个指标怎么算必须事先写死（留存按第几天、漏斗每步是什么事件、转化窗口多长）。口径不存在就先定口径，定完不再中途改。完整口径见 `references/计算口径.md`。
2. **数据形态**：标准事件表至少包含四列——用户标识、事件名、事件时间、事件属性。缺列要先说明缺什么、对结论有什么影响。
3. **对比基准**：没有基线就没有判断。基准可以是上一周期、去年同期、上线前一段时间或未受影响的人群。

## 三、标准流程

1. **定口径**：写明每个指标的计算规则和时间范围。
2. **读数据**：用 pandas / SQL 直接算，不把数据搬进新系统。
3. **查数据质量**：埋点缺失或中断、重复事件、时间字段异常、用户标识为空——先查再算，发现问题在报告开头写明。
4. **计算**：按 `references/计算口径.md` 的固定口径，不自行变通。
5. **对比判断**：和基线比，看变化幅度、是否连续出现、样本量是否够大。
6. **写报告**：按 `references/分析报告模板.md`，先给事实和数字，再给可能的解释，最后给建议动作。

## 四、七类分析速查

| 分析 | 回答什么 | 关键口径要点 |
|---|---|---|
| 事件细分 | 总量变化由哪类人/渠道/端贡献 | 按一个属性拆总量，各组占比加总应等于总量 |
| 漏斗 | 关键路径在哪一步流失 | 有序事件、固定转化窗口、按步算转化率 |
| 留存 | 用户过段时间还回不回来 | 按首次使用日分同期群，D1/D7/D30 分开算 |
| 路径 | 用户实际按什么顺序操作 | 按会话切分（默认 30 分钟无操作断开） |
| 分群 | 某类用户是否表现不同 | 先按属性或行为划定人群，再对比指标 |
| 趋势 | 指标在涨还是跌 | 时间序列 + 环比/同比，单点波动不下结论 |
| 异常判读 | 这次变化是不是真问题 | 先排除数据故障，再看幅度、持续性、同期变量 |

## 五、诚实规则（不能违反）

- 没有数据或数据缺到算不出来，直接说算不出来，不编数字。
- 样本太小，数字标注为噪声，不写成趋势。
- **功能发布后指标变化，没有随机分流时只能写「时间上相关」**，并列出同期其他变化；不写「因为上线了某功能，所以指标涨了」。
- 指标涨了不等于变好：同时检查护栏指标（例如活跃度涨了但投诉也涨了）。
- 解释和建议要分开：事实部分只写算出来的结果，推测部分明确标注。
