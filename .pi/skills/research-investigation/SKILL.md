# 四段式调研技能（research-investigation）

把一个需要外部信息才能回答的问题，走成一份**事实可核验、观点有标注、出处可点开**的调研报告。
本技能是"无人盯守也能跑"的自主调研：问题有预算、计划先过目、证据有标签、轮次有上限。

## 一、何时使用 / 先问用户什么

### 适用场景
- 用户说"帮我调研一下 / 研究一下 / 搜一下 / 查一下 XX""竞品调查""市场 / 行业调查""了解一下 XX 现状"。
- 需要外部信息才能回答、且答案要支撑某个决策：竞品动态、行业格局、政策法规、技术选型对比、市场进入判断等。
- 需要产出一份带出处的调研报告（对话内输出 markdown，或落盘到 `output/` 目录）。

### 不适用
- 纯概念解释、方法论问答——用你自己的产品知识直接回答即可（自主模式）。
- 用户自己持有上下文、需要逐题引导讨论的工作坊式访谈（不是自主调研场景）。

### 先问用户什么（澄清问题预算：最多 3 个）
调研开始前最多问 3 个澄清问题，按优先级：
1. **这次调研支撑什么决策？**（最重要——"做到什么程度算够"由决策决定；不支撑决策的研究是爱好）
2. **调研对象与范围？**（哪家公司 / 哪个市场 / 哪个主题；有无时间范围、地域限制）
3. **输出用途与篇幅？**（自己看 / 给老板汇报 / 评审材料；默认"够用模式"精简输出，用户明确要求才出详细版）

规则：用户指令里已给出的信息直接采用、不重复问；**信息不足先澄清，但 3 个问题问完或用户不回应，就带着【假设】标签继续推进，不许卡住等待**。

## 二、工作流步骤（四段式）

### 第 1 段：定提纲（研究目标 + 关键问题）
1. 用一句话写清研究目标，以及它支撑的决策。
2. 列出 3-5 个关键问题（Key Questions）——报告必须回答的问题。
3. **搜索计划门**：正式搜索前，向用户展示 3 条计划（10 秒钟能看完），用户说"改"就调整，不回应就按计划执行：
   - **搜什么**：每个关键问题对应的搜索词；
   - **来源类型**：官网 / 财报公告 / 权威媒体 / 第三方评测 / 用户社区 / 本地知识库如何搭配；
   - **如何分离事实与观点**：事实附 URL，解读标【推断】，缺口列【假设】。
   > 改计划只要 10 秒，改错方向的报告要 10 分钟——计划门是全流程最便宜的纠偏点。
4. **先查本地知识库，再联网**（历史决策 / 评测 / 案例档案里可能已有答案）：
   ```bash
   bash scripts/run-tool.sh scripts/kb_query.py --query "关键词" --type decision --top-k 3
   ```
   - `--query`：查询词（必填）；
   - `--type`：档案类型，可选 `decision|eval|case`，多类型用逗号分隔（如 `--type decision,eval`）或重复指定；
   - `--top-k`：返回条数，默认 3；
   - 输出 JSON：`{"status": "ok/empty", "query": ..., "archives": [...]}`，无结果时 status 为 empty，不算错误。
5. **问题主体是 AI/大模型领域概念或论文方法时**（如"什么是 ReAct""RAG 有哪些召回方式"），先按 **domain-kb-query** 技能查本地 AI 领域知识库（概念解读 / 精选论文 / 追踪论文三层），库内有答案就直接引用；库内没有或需要库外最新信息，再按本段联网调研。

### 第 2 段：拆子问题搜索 / 抓全文
1. 把每个关键问题拆成可直接搜索的子问题（一个子问题对应一组搜索词）。
2. 联网搜索（返回标题 / URL / 摘要的 JSON 列表）：
   ```bash
   bash scripts/run-tool.sh scripts/web_search.py --query "搜索词" --top-k 5
   ```
   - `--query`：查询词（必填）；
   - `--top-k`：返回条数，默认 5，按需要调大；
   - 输出 JSON 数组，每项 `{"title": ..., "url": ..., "snippet": ...}`；无结果返回 `[]`。
3. 对高价值结果抓正文（**摘要不足以判断时才抓，不要每篇都抓**）：
   ```bash
   bash scripts/run-tool.sh scripts/page_fetch.py --url "https://example.com" --max-chars 4000
   ```
   - `--url`：网址（必填）；
   - `--max-chars`：正文最大字符数，默认 4000，长文可调到 6000-8000；
   - 输出 JSON：`{"url": ..., "title": ..., "content": ...}`。
4. 来源搭配要求：混合来源类型（官方、财报 / 公告、权威媒体、第三方评测、用户社区）；优先近 12-24 个月的材料。
   **公告只算"意图"，必须用融资、招聘、采购、合同等硬信号佐证后才算"承诺"**——雄心出现在新闻稿里，承诺出现在财报、招聘帖和订单里。
5. 合规边界：只用公开、合法、已发布的信息；不伪装身份、不索取保密信息、不违反已接受的网站条款。判断准则：如果把你的获取方式在对方用户大会台上讲一遍会不舒服，就别用。

### 第 3 段：去重过滤（只回传摘要，防上下文膨胀）
1. 同一事实被多个来源报道时，去重保留最权威 / 最新的一条，其余记为佐证。
2. 每篇抓到的全文，先在内部消化成 1-3 句要点摘要 + 关键数据，再进入综合；**严禁把网页全文原样堆进报告或对话**。
3. 脚本返回 error（网络失败 / 抓取失败）时如实记录，换搜索词重试或列入信息缺口，**不许编造内容填充**。
4. **搜索轮次上限 3 轮**：每轮 = 拆子问题 → 搜索 → 抓全文 → 过滤摘要。每轮结束过**质量门**：
   - **来源数**：每个关键问题至少有 2 个独立来源支撑（或显式标注证据不足）；
   - **覆盖度**：全部关键问题都有证据回答，或被显式列入"信息缺口"。
   质量门达标即停；不达标才加一轮，**最多 3 轮**；3 轮后仍不达标，如实报告缺口，不硬凑结论。

### 第 4 段：综合成带出处报告
1. 按固定输出模板（见第三节）综合，**章节顺序固定不漂移**——同一主题多次调研后可直接对比差异。
2. 每条关键结论打且只打一个证据标签：
   - **【事实】**：有来源支撑，旁边附可核验的 URL + 日期；
   - **【推断】**：基于证据的解读——证据附出处，推理跳跃留给读者判断；
   - **【假设】**：为推进而做的工作性猜测，单独列出待验证。
   查不到的东西不是第四种标签，一律进"信息缺口"清单。
3. **置信度叠加**（同一动向被多个独立渠道提及时）：
   - 1 个渠道提及 → 观察项：记录，不行动；
   - 2 个渠道一致 → 工作假设：可安排人深挖；
   - 3+ 个渠道一致 → 可行动情报：可据此调整计划；
   - 渠道互相冲突 → 最值得深挖的情况：如实呈现分歧并继续挖。
4. 默认"够用模式"：只给支撑决策最强的发现，短 bullet 为准；用户明确要求才出详细版。调研的价值是决策支持，不是页数。
5. 报告以"下一步"块收尾：给恰好 4 个编号选项（如出竞品对比卡 / 出一页高管摘要 / 列下季度风险机会 / 列待验证假设的问题清单），用户可回编号、编号组合或"详细版"。

### 禁止编造清单
竞品名称、定价、市场份额、融资金额与估值、客户名单、功能发布时间、专利内容、统计数字——这些是调研类 AI 最高发的编造点。**没有可核验 URL + 日期的上述信息，一律不许写进报告**；一条没有来源和日期的"事实"，只是戴着事实徽章的观点。查不到就进信息缺口。

## 三、markdown 输出模板

```markdown
# 调研报告：[主题]
- **支撑决策**：[这次研究服务于什么决定]
- **调研日期**：[YYYY-MM-DD] · **搜索轮次**：[N/3]
- **来源概览**：共 [M] 个来源（官方 [a] / 财报公告 [b] / 权威媒体 [c] / 评测社区 [d] / 本地知识库 [e]）

## 一句话结论
[最核心的发现，1-2 句]

## 关键发现（按重要性排序）
1. **[发现]** —— 【事实 / 推断 / 假设】
   - 依据：[一句话要点]（[来源名称, 日期](URL)）
2. **[发现]** —— 【事实 / 推断 / 假设】
   - 依据：……

## 关键问题回答
### Q1：[问题]
- [回答；结论带标签，【事实】附 URL+日期]
### Q2：[问题]
- ……

## 信息缺口与待验证假设
- [没查到什么 / 哪些结论是假设，建议如何验证]

## 负面信号与风险
- [不利消息、挑战、竞争威胁——不得只报喜]

## 来源清单
| # | 来源 | 类型 | 日期 | URL |
|---|------|------|------|-----|
| 1 |      |      |      |     |

## 下一步（回复编号，可组合，或回"详细版"）
1. [后续产物 A，如：竞品对比卡]
2. [后续产物 B，如：一页高管摘要]
3. [深挖动作 C，如：下季度风险 / 机会]
4. [验证动作 D，如：待验证假设的调研问题清单]
```

落盘建议：报告可保存为 `output/调研报告-<主题>-<日期>.md`。需要网页 / PPT / 图表等演示物时，不自制 HTML，按项目规矩产出《演示需求交接单》。

## 四、呈现前质量自检清单

- [ ] 每条关键结论都有且仅有一个标签：【事实】附可点开的 URL + 日期 / 【推断】附证据 / 【假设】列入待验证
- [ ] 禁止编造清单逐项过：没有任何无出处的竞品、定价、数字、客户名、发布时间
- [ ] 关键问题全覆盖：每个问题有回答，或明确进了信息缺口清单
- [ ] 来源数达标：每个关键问题至少 2 个独立来源，或显式标注证据不足
- [ ] 来源类型混搭、以近 12-24 个月材料为主；公告类信息已标注"未经硬信号佐证"
- [ ] 负面信号 / 风险有专节，没有只报喜
- [ ] 事实与观点分离：正文陈述"是什么"，主观评价不混入事实句
- [ ] 澄清问题 ≤3 个、搜索轮次 ≤3 轮；网页全文未原样堆入，只回传了摘要要点
- [ ] 章节顺序与模板一致（便于多次调研对比差异）；结尾有恰好 4 个下一步选项
- [ ] 引用外部信息均附出处；查不到来源的说法已标注"未核实"
- [ ] 产物为 markdown；未自制 HTML / PPT 等演示物
