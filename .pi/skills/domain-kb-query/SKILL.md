# AI 领域知识库查询技能（domain-kb-query）

把用户的 AI 领域问题交给本地领域知识库检索，**基于检索到的材料回答，不凭记忆硬答可查的事实**。
知识库内容分三层：概念层（concept，项目整理的概念解读）、精选论文层（curated-paper）、追踪论文层（tracked-paper，arXiv 论文摘要）。

## 一、何时使用

### 适用
- 问概念：如"什么是 ReAct""什么是上下文工程""Agent Harness 指什么"。
- 问方法与模式：如"RAG 混合检索怎么做""反思（Reflexion）机制是什么""多智能体有哪些协作模式"。
- 问论文：如"ReAct 论文的核心结论""2210.03629 讲了什么""有没有关于 Agent 记忆的综述"。
- 问技术选型依据，且依据可能已在库内概念解读或论文中。

### 不适用（三个入口的分工）
- **项目自己的历史档案**（历史决策、评测记录、案例）→ 用 `research-investigation` 技能第 1 段的 kb_query 命令（decision/eval/case 三类档案），不用本技能。
- **库外最新信息**（近期发布、版本动态、厂商新闻）或**必须带可点开 URL 出处的外部调研**→ 用 `research-investigation` 技能联网调研。
- **产品工作方法论**（PRD 怎么写、评审怎么做）→ 用你自己的产品知识直接回答，不必查库。
- 拿不准该查哪个时：问题主体是"AI 领域知识"先查本库；主体是"我们项目以前怎么定的"查业务档案；主体是"外部世界现在怎样"联网。

## 二、怎么查

在项目根目录用统一包装器执行（自动配好解释器、PYTHONPATH、直连网络）：

```bash
bash scripts/run-tool.sh scripts/rag_query.py --query "ReAct 推理行动范式"
```

参数说明：
- `--query`（必填）：查询文本。**保留英文术语原文**（ReAct、RAG、MoE、Reflexion），中文问题可用"中文+英文术语"组合，如"ReAct 推理与行动"。
- `--top-k`：返回条数，默认 5。概念解释默认够用；要综述或对比时可调到 8。
- `--layers`：按层过滤，逗号分隔。只看概念解读：`--layers concept`；只看论文：`--layers curated-paper,tracked-paper`。
- `--category`：按分类过滤（单值），如 `--category rag`、`--category planning`、`--category memory`、`--category multi-agent`、`--category safety`。**不确定分类名就不要加这个参数**，混合检索更稳。
- `--json`：需要完整字段（arXiv 编号、source 路径、分项分数）时加；给用户回答默认不加，读人类可读输出即可。

输出读法（人类可读）：每条一段，依次是序号、标题、`[层/分类]`、相关度分数、source、正文前 200 字。
打印"未检索到相关内容"表示空结果，退出码仍是 0，不是报错。

## 三、回答纪律

1. **先查再答**：属于适用范围的事实性问题，先执行检索，不在无检索情况下凭记忆回答。
2. **判断相关性**：看前几条的标题和分数。若全部明显偏题，换一个更核心的查询词重试一次（如从"怎么让 Agent 不停下来想办法"换成"ReAct reasoning acting"）。**最多查 2 轮**（首次 + 换词一次）；仍无相关结果，明说"本地领域知识库没有收录这个内容"，并建议改用联网调研，不许硬答或编造。
3. **消化后回答**：把检索片段综合成直接回答用户问题的话，**禁止把命令输出原样贴给用户**。可以分点、可以对比，但句子要完整。
4. **注明依据**：回答末尾用一行列出依据条目的标题和层，如"依据：概念层《ReAct》、精选论文《ReAct: Synergizing Reasoning and Acting in Language Models (2210.03629)》"。论文标题中的 arXiv 编号照抄，方便用户检索原文。
5. **区分材料与推断**：库内材料直接陈述；材料之外的补充判断显式标注"这是我的推断，库内材料未覆盖"。
6. **摘要层边界**：论文层存的是摘要不是全文。用户问实验细节、完整数据等摘要里没有的内容时，说明"库内只有该论文摘要"，需要全文时用联网抓取取原文。
7. **对比类多跳问题**：如"对比 ReAct 和 Plan-and-Execute"，可分别各查一次，分别注明依据，不要用一次查询敷衍。
8. **成本**：每次查询只调一次嵌入接口，费用可忽略、无时段限制，不调用生成模型、不写库。但仍遵守 2 轮上限，不做无意义刷查。

## 四、回答前自检

- [ ] 属于 AI 领域知识问题，没有与业务档案库、联网调研的场景混淆
- [ ] 执行了检索（或有理由说明不必检索）；空结果或不相关结果没有被硬编成答案
- [ ] 回答基于检索片段，末尾注明了标题和层来源
- [ ] 没有把命令 JSON/文本原样堆给用户；材料外的推断已标注
- [ ] 查询不超过 2 轮
