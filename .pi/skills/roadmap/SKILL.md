# 路线图技能（roadmap）

把战略和需求池变成一张传达**意图与置信度**、而不是假日期的路线图。
默认用 Now/Next/Later 时间框；只有存在真实外部承诺的地方才出现日期——内部目标用置信度表达，不用日期假装确定。

## 一、何时使用 / 先问用户什么

### 适用场景
- 用户说"帮我做个路线图 / 规划下下季度（下半年、明年）做什么 / 版本规划 / 排排优先级 / Now Next Later 怎么排 / 把这些需求排成计划"。
- 已有战略方向和一堆 backlog，需要变成可对内、对外沟通的计划。
- 需要向团队或利益相关者回答："我们打算做什么、不做什么、各自有多大把握。"

### 不适用
- 没有战略 / 业务目标就要排功能清单——路线图是战略的可视化，没有战略的路线图只是穿西装的功能列表；此时先帮用户起草一段战略陈述并确认。
- 单个需求的优先级判断、单个缺陷的排期（直接讨论或用反馈分类技能，不需要整张路线图）。

### 先问用户什么（最多 3 个问题，信息不足先澄清）
1. **路线图服务于什么战略 / 业务目标？时间跨度多长？**（季度 / 半年 / 一年）——目标决定取舍，跨度决定 Now/Next/Later 的切分。
2. **受众是谁？**——内部团队 / 高管 / 销售 / 对外公布，同一张路线图对不同人详略高度不同，先确认再排版。
3. **哪些事项带着硬性外部承诺？**（合同交付、合规截止日、已官宣功能）——只有这些配写日期，其余一律不写死。

规则：用户指令里已给出的信息直接采用、不重复问；**3 个问题问完或用户不回应，就带着【假设】标签继续推进，并在路线图开头标注所采用的假设**。

可选：动手前先查本地知识库中的历史决策 / 承诺，避免路线图与既往结论冲突：
```bash
bash scripts/run-tool.sh scripts/kb_query.py --query "路线图 规划 已承诺" --type decision --top-k 3
```
- `--query`：查询词（必填）；`--type`：`decision|eval|case`，可逗号分隔多类型；`--top-k`：返回条数，默认 3。
- 输出 JSON：`{"status": "ok/empty", "query": ..., "archives": [...]}`，无结果时 status 为 empty，不算错误。

## 二、工作流步骤

1. **按主题（问题 / 结果）组织，不按功能组织。**"缩短首次价值达成时间"是主题；"新手引导向导"只是这个主题下的一个赌注。主题在单个赌注死掉后依然成立——路线图的骨架必须是主题。
2. **把赌注放进 Now / Next / Later 三个时间框：**
   - **Now** = 进行中，或数周内启动。高置信度（≥80%），有明确负责团队。
   - **Next** = Now 之后，大致本季度 / 下季度。中等置信度——形状已定但可重排。
   - **Later** = 方向性。低置信度，且明确标注为低。**不写条目数量、不估工作量**；这是兴趣声明，不是计划。
3. **每个 Now/Next 赌注必须挂四样东西**：它服务的主题、它要撬动的结果指标（outcome metric）、置信度百分比、**杀掉标准**（kill criterion——出现什么可观察的结果，就停止或转向这个赌注）。
4. **写"明确不做"清单**：3–5 个看起来合理、但被刻意排除的事项，每条一句话理由。这是对利益相关者信号量最高的一节——"不做什么"比"做什么"更能暴露取舍。
5. **写明评审节奏**（多久回看一次路线图），以及什么情况会触发计划外调整（如：关键假设被证伪、外部承诺变化、竞品重大动作）。

## 三、markdown 输出模板

```markdown
# 路线图 — [产品]，[时间跨度，如 2026 Q4–2027 Q1]，截至 [日期]
**战略**：[本路线图服务的一段话战略 / 业务目标]
**受众**：[谁] · **评审节奏**：[多久回看一次]
**假设**：[用户未回答而采用的假设；没有则写"无"]

## Now（进行中 / 数周内启动）
### 主题：[以结果表述的主题，如"缩短首次价值达成时间"]
| 赌注 | 撬动的结果指标 | 置信度 | 杀掉标准 | 负责团队 |
|---|---|---|---|---|
|      |                |        |          |          |

## Next（本季度 / 下季度，形状已定、顺序可调）
### 主题：[主题名]
| 赌注 | 撬动的结果指标 | 置信度 | 杀掉标准 | 负责团队 |
|---|---|---|---|---|
|      |                |        |          | （可暂缺） |

## Later（方向性，不承诺）
> 仅为方向性信息——排序与范围都会变化，不代表承诺。
### 主题：[主题名]
- [一句话赌注描述]（不写条目数、不估工作量、不排期）

## 已承诺日期
[仅列有真实外部承诺的事项：事项 · 日期 · 承诺性质（合同 / 合规 / 官宣）；没有则写"无"]

## 明确不做（刻意排除）
| 事项 | 为什么不做 |
|---|---|
|      |            |

## 变更记录
[自上一版以来什么移动了、为什么——首版留空]
```

落盘建议：路线图可保存为 `output/路线图-<产品>-<日期>.md`。需要做成网页 / PPT / 图表汇报时，不自制 HTML，按项目规矩产出《演示需求交接单》。

## 四、呈现前质量自检清单

- [ ] 每个赌注都挂在主题下、且对应一个结果指标；孤儿功能被质疑或砍掉
- [ ] 主题以结果 / 问题表述（"缩短 XX 时间"），不是功能名（"做 XX 向导"）
- [ ] 置信度显式标注；Later 看起来明显比 Now 不确定——若 Later 和 Now 一样笃定，就是过度承诺
- [ ] 每个 Now/Next 赌注都有杀掉标准（没有杀掉标准的路线图是棘轮：东西只上不下）
- [ ] 日期只出现在真实外部承诺旁；内部目标以置信度表达，没有写死日期
- [ ] "明确不做"清单非空且具体（3–5 条，每条带一句话理由）
- [ ] Later 区没有条目数量、没有工作量估算，且带有"方向性、会变化"的声明
- [ ] 评审节奏与计划外调整的触发条件已写明；采用的假设已在开头标注
- [ ] 产物为 markdown；未自制 HTML / PPT 等演示物
