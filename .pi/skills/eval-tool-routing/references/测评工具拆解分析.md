# AI 测评工具拆解分析

配合技能 `eval-tool-routing` 使用。内容为 2026-09 的实际查证：各工具的产品形态、实现机制、许可证与可复刻范围。结论先行：**核心没有秘密算法，护城河是云服务、生态绑定和覆盖量的体力活。**

## 一、底层结构：两个阵营，七层

| 层 | 测什么 | 关键项目/指标 |
|---|---|---|
| L1 模型能力评测 | 裸模型在公开题集的能力 | HLE、MMLU-Pro、GPQA、AIME、ARC-AGI、SWE-bench、LiveCodeBench、Chatbot Arena |
| L2 评测方法与基础设施 | 分数可信度 | lm-evaluation-harness、OpenCompass、HELM、Inspect；pass@k、Elo、LLM-as-judge；污染控制、基准饱和 |
| L3 系统工程测试 | 围绕模型的软件 | 单元（提示词/解析器）、组件（检索/工具）、集成、E2E、回归、性能成本延迟、CI/CD |
| L4 Agent 与流程测试 | 多步过程 | 任务成功率、工具选择准确率、参数正确性、轨迹评估、错误恢复、沙箱隔离 |
| L5 内容输出测试 | 说出来的话 | 格式/schema、语气、术语、可读性、事实性/幻觉、合规、指令遵循 |
| L6 在线与生产评测 | 上线后 | 影子、灰度、A/B、漂移监控、反馈闭环、人机回退率 |
| L7 组织与流程 | 持续运行机制 | eval 驱动开发、红队、golden dataset、版本管理、测试金字塔 |

L1–L2 为模型评测阵营：离线、公开、可复现。L3–L6 为业务评测阵营：场景化、私有数据、只有业务方做。L7 是连接机制。

重要事实：**「Harness」在 L2（评测框架）和 L3/L4（Agent 外壳）里是两个不同的东西**，这是常见困惑来源。

## 二、工具的四种产品形态

| 形态 | 代表 | 利 | 弊 |
|---|---|---|---|
| 命令行 + 声明式配置 | promptfoo、lm-eval-harness | 不写代码、接 CI、换模型改配置 | 复杂多步过程表达不了 |
| 代码库/测试框架 | DeepEval、Ragas、Giskard、Inspect | 能测复杂过程、自定义判分、与代码一体 | 要写 Python |
| 跑分编排框架 | OpenCompass、HELM | 批量基准、模型对比 | 只覆盖 L1–L2 |
| 观测平台（带服务端） | Langfuse、LangSmith、Phoenix、Opik、Braintrust | L6 线上监测、协作、版本 | 要部署服务、绑生态 |

没有任何单一工具同时覆盖 L1 与 L3–L7。

## 三、逐个工具拆解

### promptfoo（MIT，TypeScript，25.5k★，本机已装 v0.123）
- 资产不在算法：上百个模型端点适配、30+ 断言、红队（13 个行业方向自动生成对抗题）、本地网页界面。
- `src/assertions`：equals/contains/regex/json/bleu/levenshtein/latency/cost 为硬算；factuality/context-faithfulness/geval/llm-rubric 为「提示词+模型判定」。
- 适合 L5 主力、L6 定期重跑、L7 红队。

### DeepEval（Apache-2.0，Python，18.4k★）
- 挂 pytest，40+ 指标目录结构统一：`指标.py + schema.py + templates/`，差异主要是提示词。
- 指标含 faithful/hallucination/answer-relevancy/G-Eval/agent goal/tool/MCP/PII/bias 等；另带考题合成器、优化器、红队、模拟器。
- 适合 L3 语义断言、L4 agent 指标。

### Ragas（Apache-2.0，Python，15.9k★）
- 专攻 RAG。忠实度是两段提示词流程：先把答案拆成原子陈述（去代词），再逐句对照上下文判真假。
- 指标：忠实度、上下文精确率/召回率、回答相关性/正确性、工具调用准确率/F1、噪声敏感性、SQL 语义等价等。
- 适合 L4 RAG 组件。

### Inspect（MIT，Python，英国 AISI）
- 抽象最干净：`eval / solver / scorer / dataset / tool` 五件组合出任意评测，带 log 和 viewer。
- 适合做自建工具内核的参考。

### lm-evaluation-harness（MIT，Python，14k★）
- 资产是 1000+ 基准任务的 YAML 定义与统一执行。L1 直接调用，不重写。

### OpenCompass（Apache-2.0）/ HELM（Apache-2.0，斯坦福）
- 多基准批量编排与标准化口径，只覆盖 L1–L2。

### Giskard（Apache-2.0，Python）
- 扫描器 + 对抗题生成，覆盖幻觉/注入/偏见；企业版闭源。

### Arize Phoenix（**Elastic License 2.0**，Python/TS，11.6k★）
- 由 phoenix-client / phoenix-evals / phoenix-otel / sqlean 组成，OpenTelemetry 追踪 + 本地评测。
- ELv2 限制：**可改自用，不能提供托管服务，不能提供其付费管理功能**；不可混入 MIT/Apache 代码。

### Langfuse（MIT 主体 + **ee/ 商业许可**，TS，35k★）
- ClickHouse + Postgres + worker 架构；ee/ 目录（SSO、审批、高级评估）不可碰。
- L6 平台能力最强，但本项目不建服务端，不学代码只学架构。

### 闭源商业平台（仅 SDK 开源）
- LangSmith（SDK MIT）、Confident AI、Braintrust（SDK Apache）：核心是「存调用记录→网页看→跑评测→管版本→标注队列」，无算法秘密，是数据库+网页工程量。

## 四、复刻可行性汇总

| 工具 | 许可证 | 可复刻 | 限制 |
|---|---|---|---|
| promptfoo | MIT | 全部思路 | TS 代码需用 Python 重写；百个模型适配不值得逐个做 |
| DeepEval | Apache-2.0 | 全部指标模板 | 保留版权声明 |
| Ragas | Apache-2.0 | 全部流程 | 同上 |
| Inspect | MIT | 五件抽象 | 无 |
| lm-eval-harness | MIT | 直接当 L1 内核调用 | 不必重写 |
| OpenCompass/HELM | Apache-2.0 | 编排思路 | 只覆盖 L1–L2 |
| Phoenix | ELv2 | 只学架构 | 不能托管、不能混许可证 |
| Langfuse | MIT + ee | 主架构可参考 | ee/ 不碰 |
| Giskard | Apache-2.0 | 核心扫描器 | 企业版闭源 |
| LangSmith/Confident/Braintrust | 闭源 | 只还原概念 | 看不到源码 |

可做得更好的三点：① Inspect 骨架 + DeepEval/Ragas 指标 + promptfoo 红队合一，市场无此组合；② 统一覆盖 L1–L7；③ 中文判分口径（现有模板为英文设计）。

## 五、实现机制的本质

语义类指标统一模式：**精心写的提示词 → 要求模型按 JSON schema 输出判定 → 代码解析聚合成分**。传统类指标（正则、BLEU、ROUGE、编辑距离、延迟、费用）是普通工程。因此复刻难度低，成本是逐个移植指标模板的体力活。

## 六、推进路线（当前：skill 形态，按需融合）

1. 现阶段用 `eval-tool-routing` 技能调度现有工具，不提前造轮。
2. 每次调用记入 `调用登记.md`。
3. 同一路径走过两次以上且验证可用 → 固化；现有工具满足不了 → 启动自建。
4. 自建顺序：Inspect 五件为内核 → L1 直接调 lm-eval-harness → L3–L5 按 Apache 许可移植 DeepEval/Ragas 模板 → 红队与断言参考 promptfoo 用 Python 重写（不复制代码）→ Phoenix/Langfuse 只学架构。
5. 自建工具以 Apache-2.0 发布，与上述许可证兼容。
