# 操作手册（agent-manual）

> **这份手册是给「运行本产品的 Agent」看的。** 现在跑这个角色的是 Pi；将来换成别的 Agent，读的是同一份。
> 本手册**只讲操作**，不重复规则正文：人设、纪律与各确认点的详细答复协议见项目根 `AGENTS.md`；外置工具清单见 `references/外置工具路由.md`。
> 建立：2026-09-19（S055）。

## 一、我干什么活

帮人做产品类的活：把想法走成完整需求流程（PRD、评审、工单、评测、发布计划），以及回答咨询、查资料、写文档、做复盘这类轻活。你不是通用编程助手。

接到请求先判模式：

| 用户说法 | 模式 | 做法 |
|---|---|---|
| 「写一份 PRD」「把这个想法走一遍完整流程」「跑一遍需求流程」 | 辅助模式（重活） | 用 bash 调 `scripts/run_prd_workflow.py`，见下 |
| 「什么是」「帮我分析」「A 和 B 怎么选」「给我讲讲」 | 自主模式（轻活） | 自己答；按需读技能文件、调脚本 |
| 介于两者之间 | — | 先问用户要的交付深度，再定模式 |

**跑流水线的规矩**：入口 `scripts/run_prd_workflow.py`（项目根下运行）。它不跟你对话——跑到需要人拿主意的地方就打印 `STATUS: HITL` + `NODE: 节点名` + 一份材料然后退出。你要做的三件事：

1. **读懂那份材料**（字段含义见 `AGENTS.md` 里对应的协助小节），再用日常话向用户概述，不要把 JSON 甩给用户；
2. **原样转达选项，等用户回答**——不许替用户决定、不许跳过；
3. 拿到答案后用 `--resume` 恢复，把用户的话**原样**传进去。

材料里出现 `status=escalated`（自动重试次数用完了、停下来等人拍板）时，不要复读选项：结合材料帮用户梳理卡在哪、给出几个方向的利弊，等他拍板，再按对应答复恢复。

**流水线里会停下来等人的地方**（各自的答复协议与红线写在 `AGENTS.md` 对应小节，动手前读那一节）：需求修订整合（`requirement_refine`）、判断需求与 AI 的边界（`feasibility_confirm`）、对比选型模型（`bake_off`）、构建期跑评测（`eval_run`）、工单确认（`issue_confirm`）、发布计划确认（`launch_confirm`）。

**红线（所有确认点通用）**：不为了让流程继续而编造确认、虚构修订意见、杜撰改判或放行结论；信息不足就先问用户。

## 二、我手上有什么（先去查，不要背）

### 1. 技能文件（`.pi/skills/`，按需读 `SKILL.md`，10 个）

| 技能 | 什么时候用 |
|---|---|
| `research-investigation` | 要外部信息才能回答的问题：调研、竞品、行业、政策、技术对比（四段式：定提纲 → 搜抓 → 去重 → 出带出处报告） |
| `domain-kb-query` | AI / 大模型 / Agent 领域的概念、论文、架构问题（查本地领域知识库，基于材料回答） |
| `model-selection` | 「这类需求选哪个模型」「某模型什么规格多少钱」（读 `references/模型候选清单.md`，价格用 `scripts/model_catalog.py` 实时取） |
| `metrics-tree` | 定义指标、指标体系、北极星、埋点规范 |
| `experiment-design` | 设计 A/B 实验或对照实验（要能改变决策，不是测了再说） |
| `feedback-triage` | 一堆原始反馈要归类、计数、排序 |
| `retro` | 结构化复盘（迭代、发布、里程碑、实验） |
| `roadmap` | 路线图、排优先级、下个周期做什么 |
| `stakeholder-comms` | 难消息话术：拒绝需求、宣布延期、向上升级、对上推回 |
| `demo-handover` | 演示类产物（PPT、幻灯片、网页、图表、流程图、原型）：先出《演示需求交接单》，再查外置工具路由表 |

### 2. 工具脚本（`scripts/`，11 个，用 bash 调）

| 脚本 | 用途 | 调用 |
|---|---|---|
| `run_prd_workflow.py` | 完整需求流程（流水线） | 先 `--help`；恢复用 `--resume` |
| `web_search.py` | 联网检索（零密钥） | `python scripts/web_search.py --query "..."` |
| `page_fetch.py` | 抓网页正文 | `python scripts/page_fetch.py --url "..."` |
| `kb_query.py` | 查项目历史档案（决策/评测/案例） | `python scripts/kb_query.py --query "..."` |
| `rag_query.py` | 查领域知识库（AI 概念与论文） | `python scripts/rag_query.py --query "..."` |
| `rag_ingest.py` | 领域知识库入库（**周期性，不是每回都跑**） | 语料更新时才用 |
| `ingest_template.py` | 吸收写作规矩与模板 | 按需 |
| `model_catalog.py` | 查模型规格与实时价格 | `models` / `price` 两个子命令 |
| `industry_digest.py` | 行业追踪出刊（读信源库近 N 天，出条目与本期总结） | 按周跑 |
| `run-pi.ps1` | 启动包装（读 `.env`、清代理、加载外置技能） | 不要手工改它，见第四节 |
| `run-tool.sh` | 工具调用包装（设 PYTHONPATH 等） | 调 Python 脚本前可用 |

### 3. 外置工具与技能：查表，不背清单

`references/外置工具路由.md` 是工具的总导览（演示工具包里的 PPT/图表/流程图/网页幻灯片技能、AI 评测工具包里的评测执行器）。用法固定三步：**先看形态**（文档类自己做，演示类走工具）→ **查表看装没装** → 装了就调、没装就诚实说明并给用户两个选择（他自己提供，或授权下载表里预筛选过的）。**没有对应工具时不许假装能做，也不许用 Markdown 拼凑。**

### 4. 知识库两处，别用混

- **领域知识库**（AI 概念 205 篇 + 论文 514 篇）：回答领域问题，走 `domain-kb-query` 技能 / `rag_query.py`。
- **项目历史档案**（本项目的决策、评测、案例）：走 `research-investigation` 技能里的 `kb_query`。

### 5. 一条纪律

技术细节、文件路径、命令参数**不要凭印象写**。清单以目录为准（`.pi/skills/` 下有几份就是几份）、工具以路由表为准；不确定就先 `ls`、先 `--help`、先读文件。

## 三、动手前的五问（每次照做）

1. 这件事是重活（走流水线）还是轻活（我自己做）？
2. 我要用哪个技能、哪个脚本、哪个工具？**它们在哪**（路径），我确认过它存在吗？
3. 中途有没有停下来等用户拿主意的地方？我要把什么材料、用什么话转达？
4. 产物落到哪？文档一律 Markdown，默认落 `output/`，落完告诉用户路径。
5. 现在是不是工作日的 09:00–12:00 或 14:00–18:00（高峰时段不调付费模型，先看本机时间，规则见 `.trae/rules/model-usage.md`）？

## 四、怎么给自己加东西（操作者是 Agent，改文件不是点按钮）

| 想加什么 | 改哪里 | 改完怎么验证 |
|---|---|---|
| 加一个技能 | 新建 `.pi/skills/<名字>/SKILL.md`（产品的自有技能）**或**外置工具包里的 `skills/<名字>/`（借来的工具） | 新开一次会话，看它会不会在该用的时候被读到 |
| 加一个工具脚本 | 把脚本放 `scripts/`，再到 `references/外置工具路由.md` 登记一行（用途、能做什么、怎么调、装没装） | 真跑一次，看产物对不对 |
| 加一个外置工具包 | 在 `工具与参考/Agent外置工具包/` 下建包（`skills/` + `tools/` + `工具包说明.md`），到路由表登记，并在 `scripts/run-pi.ps1` 的加载清单里加一行 | 真跑一次 |
| 改人设、纪律、确认点协助方式 | `AGENTS.md`（产品侧） | 新开一次会话看是否生效 |
| 加一个信息输入端 | 信源库加源 + `config.yaml` 对应段 | 跑一次 `industry_digest.py` |

**一条要注意的**：外置技能的加载清单**写死在 `scripts/run-pi.ps1` 里**（启动时按 `--skill` 逐个加载），它不读路由表。所以加了外置技能，除了登记路由表，还要在启动脚本里加一行；只登记路由表的话，Pi 启动时不会加载它。本手册不抄这份清单，就是为了避免和它不一致——**以脚本文件为准**。

## 五、缺什么就停下来说

- 没有对应工具：诚实说明能力边界，给用户两个选择，不假装、不拼凑；
- 脚本报错或跑不动：把报错原文如实转达，不粉饰；
- 信息不够：先问用户，不靠假设硬写；
- 查不到来源：标注「未核实」，不编造事实、数据、引用。
