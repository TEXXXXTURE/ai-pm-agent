## 一、背景与问题

流水线 Agent 和综合对话 Agent 做完后，各自只有命令行和内部接口，没有统一的、面向人的操作界面。现在对话类操作走命令行对话、流水线操作走命令行参数——**每增加一个 Agent，就要单独配一个前端**，重复且割裂。

## 二、产品定位与目标

**一句话定位**：一套统一的网页前端，接入所有 Agent；以后任何 Agent 只需登记接入，不再单独做前端。

- 对话式 Agent 在工作台里呈现为**对话框**；
- 流水线式 Agent 在工作台里呈现为**画布**（每个步骤可看、可调）；
- 新增 Agent = 登记它的输入输出接口，工作台外壳代码零改动。

产品不售卖，供自己、朋友和社区使用，扩展性优先。

## 三、目标用户

- 主要使用者：操作者本人，且大概率是 Agent（通过规则告诉 Agent 如何登记和修改，不做给人看的极简表单）；
- 次要使用者：需要查看流水线运行状态、在固定确认点做答复的真人。

## 四、产品范围

### 4.1 本期做

1. 工作台固定外壳：对话框、画布、侧边栏；
2. 流水线 20 节点的画布可视化（查看运行状态、调整参数）；
3. 按钮/入口的可插拔登记机制；
4. 画布编辑导出结构化文件，供 Agent 读图定位源码、改单个模块；
5. 多 Agent 接入协议（连接登记 + 角色登记）。

### 4.2 明确不做

| 不做 | 原因 |
|---|---|
| 整个前端可自由定制 | 工作台是固定壳，只扩展按钮和入口（VS Code 插件模式） |
| 画原型 → 自动生成整个前端 | 现有工具产不出生产级代码（缺设计契约），不是本项目路径 |
| 插件市场 / 社区一键导入 | 自用规模，只保留「安装登记」动作，不建市场 |
| 服务端执行任意代码的插件 | 安全与调试成本不划算 |
| 在对话里嵌网页做插件界面 | 与宿主主题、快捷键、状态同步成本高 |
| 自造标记语言或私有格式 | 一律用普通 JSON + 公开字段说明 + 版本号 |
| 多租户权限、云端/自建分裂 | 单机自用，没有这个威胁场景 |
| VS Code 全套贡献点（38 个） | 先做三个：命令、视图（面板）、菜单挂点 |
| 常驻菜单栏与后台定时任务 | 本产品不是常驻类应用 |

## 五、产品方案

### 5.1 总体形态

```
┌─ 工作台（统一前端）────────────────────────┐
│  [对话框]（对话 Agent）   [画布]（流水线 Agent）│
│   · 聊天输入/输出         · 节点+连线可视化     │
│                          · 每步可看可调        │
└────────────────────────────────────────────┘
        │                        │
        ▼                        ▼
  综合对话 Agent            流水线 Agent（20 节点）
```

### 5.2 对话框

对话式 Agent 的界面：聊天输入、聊天输出、历史记录。承接流水线在固定确认点的提问与答复，支持暂停后从上次停下的位置继续。

### 5.3 画布（流水线 Agent 的界面）

- **节点块**：流水线 20 节点逐个画成方块；
- **连线**：节点间的线性边和条件边，条件边上标注路由条件（如「判定为 AI 核心需求 → 走 AI 路线」）；
- **可调旋钮**：节点上的提示词、阈值、及格线、配置参数。

画布有两种用途：

1. **查看**：运行时显示当前走到哪个节点、每步的输入输出；
2. **调整**：改参数、改连线、往节点上挂外部技能或工具。

### 5.4 核心价值：解耦后模块可中途插入

现有节点通过节点依赖容器获取一切（提示词、执行器、工具目录），节点本身不关心这些东西从哪来、是谁装的。因此增强某个节点 = 换它的提示词或挂一个外部技能，**其余节点零改动**。

示例：评审节点挂上一个更强的外部评审技能，评审能力增强，其余 19 个节点不动，改动面和测试面都小。

### 5.5 按钮可插拔（VS Code 插件模式）

- 工作台外壳固定，可扩展的是**按钮/入口**，像 VS Code 装插件后左侧出现新图标；
- 每个按钮 = 一个功能、Agent 或工具的入口 = 前后端接口；
- 按钮是预定义的可插拔入口，不手动绘制：登记一条按钮定义（图标、名称、连哪个接口、什么语义）后出现在工作台；
- **加按钮 = 登记一条入口定义**，与「外置工具路由表加一行 = 加一个工具」完全同构；
- 按钮打开后的界面可用组件拖拽方式定制，产物必须是结构化 JSON（人和 Agent 都能读），不接受私有格式。

### 5.6 画布改代码的机制

1. 人在画布上摆节点、连线、调参数（可附文字说明）；
2. 前端把画布翻译成**结构化文件**（节点 + 边 + 参数，序列化 JSON）；
3. Agent 读结构文件（不读屏幕截图），对照[流水线模块拓扑清单](../references/流水线模块拓扑清单.md)定位到对应源码；
4. Agent 只改那一个模块（或派单修改）。

画布产出的是一份「改造说明书」，Agent 照它改 `src/` 代码；**流水线实际运行的仍是代码，不是画布文件**。先例：n8n、Dify、ComfyUI 均为画布序列化 JSON 后交给引擎，Agent/引擎读结构不读像素。

### 5.7 多 Agent 接入

- 工作台是前端外壳，不绑定具体 Agent；每个 Agent 只需暴露输入接口和输出接口；
- **有接口端点的 Agent**：一律先按 OpenAI 兼容端点接入（登记一个地址和密钥即可，不用插件和中间件）；
- **命令行型 Agent**（如 Claude Code 这类）：界面负责选模型、选工作目录、登记启动参数，点击后在终端启动；
- 新增 Agent = 登记后复用这套前端，不做新前端。

## 六、数据与登记规范

### 6.1 两层登记（32 款现成产品一致的做法）

| 层 | 登记内容 |
|---|---|
| 连接登记 | 后端服务：协议类型 + 地址 + 密钥 + 模型 ID 列表，逐个模型标注能力（工具调用/视觉/音频） |
| 角色登记 | 模式或 Agent：名称 + 图标 + 说明 + 系统提示词 + 挂哪些技能/工具/资料 + 从哪触发 + 启用开关 |

### 6.2 画布文件格式

- 按 `nodes` / `edges` / `viewport` 三块分开存放（依据 Dify 结构）；
- 分两份产物：
  - **编辑态**：给人看，带位置、分组、颜色；
  - **执行态**：给引擎和 Agent 读，只有「节点 → 类型 + 输入」，连线内联（依据 ComfyUI 的 Save Format / API Format）；
- 位置坐标不进逻辑定义，避免挪动节点产生无意义差异、给模型制造噪声。

### 6.3 入口三张表

命令表、视图（面板）表、菜单挂点表。「如何新增一个模式」本身必须写成一条有文档的固定路径（前端、后端各登记一处），否则加几次就会中断。

## 七、技术选型（调研已验证）

| 用途 | 方案 | 说明 |
|---|---|---|
| 画布渲染与编辑 | React Flow 类开源画布 | 不自己造画布引擎 |
| 按钮界面的拖拽定制 | Puck / MUI Toolpad Studio / OpenPage（均开源 MIT） | JSON-first 是入选硬条件 |
| 界面生成（可选） | Lovable / Bolt / v0 类工具 | 须生成标准 React，禁止私有格式 |
| Agent 接入 | OpenAI 兼容端点 | 外部 Agent 的统一入口 |

## 八、实施步骤

| 步 | 内容 | 依赖 |
|---|---|---|
| 1 | 只读可视化：20 节点和条件边画成画布 | 流水线模块拓扑清单（已建） |
| 2 | 可编辑：拖拽、连线、改参，导出结构化 JSON | 步 1 |
| 3 | Agent 读 JSON → 定位源码 → 改单个模块（半自动） | 步 2 + 节点插槽规范 |
| 4 | 多 Agent 接入协议（对话框 + 画布统一外壳） | 步 3 |
| 5 | 外部技能/工具挂到节点，在画布上增强节点能力 | 步 4 |

## 九、验收标准

1. 一个新 Agent 通过两层登记即可接入工作台并获得对话框或画布界面，**工作台外壳代码零改动**；
2. 画布完整展示 20 节点与条件边；运行时可查看当前节点及每步输入输出；
3. 画布编辑产出 `nodes`/`edges`/`viewport` 结构文件，编辑态与执行态分离，位置信息不进执行态；
4. Agent 读执行态文件能定位到源码模块；对单个节点做一次外部技能挂载增强，其余节点零改动，流水线回归测试通过；
5. 加一个按钮只需在入口定义登记一条，按钮的用途在登记时显式写明，不依赖猜测；
6. 固定确认点在界面上可暂停、可继续，无答复时不放行。

## 十、前置依赖与启动时机

- **前置**：① 流水线全部完结；② 内部优化完成（对话 Agent 层能主导流水线、节点插槽机制成熟）；
- 地基已就位：流水线模块拓扑清单、画布式需求表达设计共识；
- 在前置满足前，本产品只保留规划，不动工。

## 十一、主要风险

1. 节点/Agent 的接口契约不成熟，按钮和画布无法对接——必须先定义契约再做界面；
2. 拖拽或自动生成产物若为私有格式，Agent 无法读取和修改——JSON-first 为硬性要求；
3. 按钮用途靠猜会导致语义错乱——用途必须人工登记、显式声明。
