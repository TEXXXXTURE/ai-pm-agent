# AI PM Agent

给产品经理用的工作流助手。丢一段需求描述进去，它按固定顺序走完一套产品流程，每一步交出一份 Markdown 文档。

它做的是产品经理的活：把需求问清楚、判断这事值不值得做、写方案、请人评审、拆研发工单、定上线计划。写代码、修 bug、搭工程不在它的范围里。你可以拿它当咨询对象问「这两个方案选哪个」，也可以让它把一句粗糙的想法从头走到上线计划。

[![tests](https://github.com/TEXXXXTURE/ai-pm-agent/actions/workflows/tests.yml/badge.svg)](https://github.com/TEXXXXTURE/ai-pm-agent/actions/workflows/tests.yml)

```
接需求 → 需求分析 → 写 PRD → 评审 → 设计评测 → 对比选型 → 拆工单 → 构建期评测 → 发布计划 → 写成文件
```

## 跑一遍是什么样

```bash
PYTHONPATH=src python scripts/run_prd_workflow.py --requirement "给社区团购加自动拼单"
```

它先复述需求、给一个「算不算 AI 需求」的判断，然后停在第一个确认点等你回话：

```
STATUS: HITL   NODE: requirement_confirm   THREAD_ID: 8f3a1c...
需求原文：给社区团购加自动拼单
模型判断：算 AI 核心需求（要用模型匹配商品与参团人数）
请确认需求原文，以及走 AI 轨道还是普通轨道。
```

你回一句「确认」，它接着跑。全程有 8 处这样停下来等人的地方。跑完产物是文件：

```
output/社区自动拼单/
├── 需求文档.md      PRD
├── 洞察.md          用户、场景与缺口
├── 评审报告.md      五维评分 + AI 维度专项检查
├── 研发工单.md      按「用户能做完一件事」切的工单
├── 发布计划.md      7 步发布计划
└── 就绪度打分.md    11 个维度打分，达不到的档位直接标出来
```

跑到一半想停也可以，`--resume <THREAD_ID>` 从上次停的地方接着跑。

## 装起来

需要 Python 3.11+。

```bash
pip install -r requirements.txt
cp .env.example .env        # 填模型密钥，默认读 DEEPSEEK_API_KEY
```

测试不需要密钥，全部跑本地假模型：

```bash
PYTHONPATH=src python -m pytest tests/ -q        # 819 passed
```

模型默认走 DeepSeek，也支持 Anthropic、Gemini、Ollama。在 `config.yaml` 的 `llm.providers` 里取消注释就能换；密钥只从环境变量读，不写进文件。

## 用之前要另外准备什么

仓库里只有这个产品本身。密钥不在里面，跑评测、画图、做演示的工具也不在里面。用得上的时候，照 `references/外置工具路由.md` 那张表装好、登记路径：

| 用来做什么 | 装什么 | 装在哪 |
|---|---|---|
| 跑考题、给候选模型打分 | Promptfoo | `工具与参考/Agent外置工具包/AI评测工具包/` |
| 画流程图、架构图 | mermaid-cli | `工具与参考/Agent外置工具包/演示工具包/` |
| 做 PPT、网页演示 | 演示工具包 | 同上 |
| 查 AI 概念与论文 | ChromaDB + 嵌入模型 | 本地 `domain_kb/` |

`工具与参考/Agent外置工具包/` 被 `.gitignore` 排除，不进仓库；领域知识库的语料要你自己准备。

## 几个当时想清楚的选择

**判断放代码里，内容交给模型。** 评审过不过、评测达不达标、工单结构合不合理，都由代码按数值算出来。这样同一份输入跑两遍结论一样，换个模型也不会跟着飘。

**该人拍板的地方就停下来。** 全程 8 处停下来等你回话——从确认需求原文，到评测没达标时选修复方向，到最后的发布计划。它不替你选，也不催你。

**流水线跑不了的活，放到项目外面做。** 跑评测、画图、做演示，市场上都有成熟工具，自己从头做反而做不好。这些活交给外面的工具，流水线只管把数据递出去、把结果收回来；装什么、装在哪、怎么调，写在一张路由表里，换工具不用改流水线代码。

**产物只有一种格式。** 所有文档都是 Markdown，落在 `output/` 下。PPT、图表、原型这类演示物不算文档，交给外面的工具做。

## 仓库结构

```
src/            流水线内核：节点、判定、状态机、提示词、校验
tests/          819 个测试
scripts/        入口脚本（run_prd_workflow.py 等）与工具脚本
artifacts/      产物模板
.pi/skills/     内置 Agent 的 PM 技能与操作手册
references/     项目自己写的参考：工具路由表、模型候选清单、流水线拓扑
docs/           核心规格：PRD、技术设计、工作流设计、职能标准调研
AGENTS.md       给运行本产品的 Agent 读的人设与纪律
```

仓库里只有产品本体。会话记录、任务书、调研草稿这些开发过程文档留在本地，不上仓库。

## 还没做的

- 上线后的灰度监控和数据回流考题集只有接口，没实现
- 演示类产物（PPT、图表、原型）依赖外面的工具，装不上就只能停在交接单
- 领域知识库要自己建库；没有语料时，那一段的检索会直接跳过
