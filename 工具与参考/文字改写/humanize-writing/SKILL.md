# 文字改写

> 整合来源：cn-humanizer（模式清单+词汇黑名单主体）、stop-slop-zh（补充词汇）、deslop-text（自查思路）、Structured Brief（场景模板）。2026-09-12 整理。 <!-- [MA 2026-09-12] -->

## 什么时候用

用户明确表示对表述不满意，或要求改写、润色、去 AI 味。日常输出的表述规则在 AGENTS.md 的「表述规则」节；本技能处理事后修改。

## 先问什么

1. 改哪份文字（用户粘贴，还是给文件路径）。
2. 不满意的是什么（对不上路由表时问一句）。
3. 保持什么语气（工作汇报默认：直接、清楚、有事实；不加口语和情绪）。

## 路由表

| 不满意的情况 | 改写方式 | 查哪份材料 |

| 看不懂，有代号、新词、缩略 | 展开：把代号还原成事情本身 | 本文件「直述改写」 |
| 太长、废话多 | 删：砍填充词、重复句、空总结段 | references/模式清单.md 第 2、7 条 |
| 一眼假、AI 味重 | 逐条查改 | references/词汇黑名单.md + references/模式清单.md 全表 |
| 空话套话多、全是形容词 | 换具体：拔高说法换成事实和数字 | references/模式清单.md 第 1、4 条 |
| 结构乱、抓不住重点 | 套场景模板重排 | references/场景模板.md |
| 翻译腔、不像中文 | 按中文语序重写 | references/模式清单.md 第 18 条 |

## 直述改写（处理代号和新词）

1. 找出文中自造的缩略、代号、新词（判断标准：读者不知道它指什么）。
2. 每处替换成它指的事情本身：谁、做什么、结果是什么。
3. 事情名太长的，前文说一遍全称，后文可用短指代，但指代对象必须唯一。

## 改写步骤

1. 通读原文，对照路由表标出问题点，先标不改。
2. 查对应材料，逐条改。只删、换、重排；不新增观点、不编造事实、不改原意。
3. 跑质量自检（见下）。
4. 交回：改后全文 + 一句话说明改了哪类问题。说明要具体（"删了 3 处套话结尾，2 处代号展开成具体事情"），不写"优化了表达"这类空话。

## 质量自检

- [ ] 词汇黑名单一级词清零；二级词每段不超过 1 个。
- [ ] 没有"综上所述""值得注意的是""不仅…更是…"这类模式句。
- [ ] 每句主谓宾完整，读者一遍读懂。
- [ ] 原意未变：改写前后的事实、数字、结论一致。
- [ ] 语气匹配场景：工作文体不硬加"说实话""踩过坑"这类口语。
- [ ] 第一句就是结论或答案。
