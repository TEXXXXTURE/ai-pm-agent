## 五、跨厂商限制与坑（与具体型号无关，容易踩）

1. **`temperature` 在部分新模型上不可用**：GPT-5.x、o 系列不支持 `temperature`/`top_p`/`max_tokens`，要用 `reasoning.effort` 与 `max_completion_tokens`（外部参考 2026-01-28）。把这类模型塞进为旧模型写好的调用代码会直接报错。
2. **「上下文大」不等于「能一次写长文」**：要同时看最大输出。表内 `minimax/MiniMax-M2.5`（1M 上下文 / 8,192 输出）、`deepseek-chat`（131,072 / 8,192）都是读得长、写不长的配置（表内字段）。
3. **思考/推理模式吃输出额度**：Claude extended thinking 的思考 token 按输出价计费（外部参考 2026-01-28）；DeepSeek reasoner 的思考 token 计入输出计费（外部参考 2026-01-28）。按纯输出字数估算成本会偏低。
4. **超长上下文有分档涨价**：Claude Sonnet 4.5 与 Gemini 2.5 Pro / 3 Pro 在外部参考里都有「超过某档位后单价上浮」的说法（外部参考 2026-01-28）。litellm 表**不体现分档**，只给一个价（表内字段），长文预算要按升档留余量。
5. **国内厂商在表内多档并存且部分缺价**：千问在表内同时存在型号名与日期快照版本（如 `dashscope/qwen-plus` 与 `dashscope/qwen-plus-2025-07-28`，两者上下文标值还不同）；豆包全系、`dashscope/qwen3-max` 没有单价；GLM、DeepSeek、Kimi 另有裸 key 条目（如 `glm-4-7-251222`、`deepseek-v3-2-251201`、`kimi-k2-thinking-251104`，provider 归 volcengine）（以上均为表内字段）。接入前必须锁定具体版本 id，不要用「型号名」直接上线。**缺价不等于免费**：跑 `price` 会打出「缺价」提示，须向厂商问价。
