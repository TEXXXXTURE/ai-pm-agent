# 外置工具路由表（Agent 查工具先查这里）

> PM Agent 遇到**非 Markdown 产物**需求（做演示/画图/做 PPT/做网页）或需要**通用执行器**（批量模型评测）时，先查本表：
> ①该形态有没有对应工具；②工具装没装；③装了去哪调用，没装怎么获取。
> 外置分两类（workflow-design.md v3.0 原则 4）：**产物能力外置**（演示工具包，Agent 本体做不了的产物）与**执行器外置**（AI 评测工具包，无状态机械执行器；工作流主干在 `src/`）。
> 工具实体在项目内：`工具与参考/Agent外置工具包/`（各包装箱单见包内 `工具包说明.md`），该目录由 .gitignore 排除不进 git。
> **本表登记的工具不在本仓库**：克隆本仓库只拿到路由表，拿不到工具实体与运行依赖。
> 建立：2026-09-10；2026-09-12 随用户迁入项目内，同日新增 AI 评测工具包节。

## 零、判断序：什么放进循环，什么放 SOP，什么根本不接

> 用途：新增任何能力前先过这四问，决定它长在哪里。**循环**=每次跑图都会经过的确定性代码路径（判定与门（停下来等确认的地方））；**SOP**=规则/路由/清单文本（人读、Agent 也读，读到才去调）；**外置实体**=可替换的执行件（脚本、工具包、技能、语料）。
> 建立：2026-09-15。

1. **每次循环都要用吗？** 不是 → 放 SOP + 外置实体，不进内核代码路径。
2. **换个需求/领域还成立吗？** 只在某个领域成立 → 知识进 RAG 语料，能力进工具包；领域**功能**（某个产品自身要做的事）不进本项目。
3. **是「判定」还是「执行」？** 执行可外置（谁家的执行器都行），判定留内核（代码硬判）。
4. **是「契约」还是「内容」？** 契约（schema、门、状态字段）留内核，内容（模板、语料、示例、措辞）放外置。

一句话判定标准：**执行可外置，判定留内核；内容可外置，契约留内核；偶尔用放 SOP，每次用才进循环。**

### 落地结果（2026-09-15 盘点）

- 属于第①②问「该外置」但**仍长在内核**的：Promptfoo 适配层（`src/nodes/eval_run.py`、`bake_off.py` 内的配置生成与结果解析）、RAG 建库链路（`src/kb/rag/` 的 ingest/splitter/embeddings）、工具目录解析器（`src/components/tools/tool_catalog.py`）、两个无写入方的死字段（`state.metrics_tree`、`state.experiment_design`）。
- 已在外部、本次补登记的通用执行器见第二节之二。

## 一、使用规则（给 Agent）

1. **先判形态**：用户要的是文档（PRD/报告/纪要 → Markdown，你自己做）还是**演示物**（PPT/网页幻灯片/数据图表/流程图/泳道图/思维导图/视频）？演示物不走 Markdown，走本表。
2. **先出交接单再动手**：演示需求先按 `demo-handover` 技能澄清五要素（演示什么/受众/核心结论/数据素材/期望形式），信息不全先问。
3. **查表定位**：按"期望形式"找到对应工具行，看**安装状态**：
   - **✅ 已装**：按"调用入口"加载技能、按技能指引制作；产物落 `output/`。
   - **⏳ 未装/待配环境**：明确告诉用户"该工具尚未就绪"，给出两个选择——**①用户自行提供工具**（放进外置包 skills/tools 并通知登记）；**②授权 Agent 下载本表已预筛选的工具**（说明来源、用途、安装方式，经用户同意后执行，装完更新本表状态）。
4. **不许假装能做**：没有对应工具时，不得硬用 Markdown 拼凑演示物，也不得编造工具调用结果；诚实说明能力边界（G8）。
5. **用完登记**：新装/更新工具后，更新本表与外置包 `工具包说明.md` 的状态。

|---|---|---|---|---|---|
| 离线评测 / 候选模型对比测试（bake-off） / 构建期准入门（停下来等确认的地方）（v3.0 第 5/6/8 段） | Promptfoo 0.123.0 | 能做：YAML 配置驱动批量调模型、几十种断言匹配器、红队用例生成、JSON/HTML 报告、退出码 0/100/1，原生 DeepSeek provider；不能做：生成产物类输出（PPT/网页）、不写流程判断逻辑、不替代人工评审；调用前提：只连项目自有 DeepSeek（读 `.env` 的 `DEEPSEEK_API_KEY`、直连清代理、遵守峰谷铁律），CLI 路径见调用入口 | https://github.com/promptfoo/promptfoo （MIT） | ✅ 已装（2026-09-12）：本地 npm 装于 AI 评测工具包；3 题冒烟直连 deepseek-v4-flash 全过（721 tokens、退出码 0，报告 `output/ai-eval-smoke/results.json`） | 技能目录：`工具与参考/Agent外置工具包/AI评测工具包/skills/ai-eval`（Pi 经 `--skill` 加载）；CLI：`AI评测工具包/tools/promptfoo/node_modules/.bin/promptfoo`；配置样例：`AI评测工具包/examples/` |

## 二·之二、通用执行器（项目内脚本，按需调用）

> 性质：既不是产物能力、也不是评测执行器，而是**按需调用的通用执行器**（调研、抓取、语料入库、知识检索）。它们在 `scripts/`，不入内核代码路径；SOP 里写清用法，Agent 读到即调。
> 登记：2026-09-15（按第零节判断序盘点补登记）。

| 用途 | 脚本 | 能做什么 | 调用入口 | 频率 |
|---|---|---|---|---|
| 联网检索资料（需求调研） | `scripts/web_search.py` | 关键词检索，返回标题/URL/摘要；零 API key（DuckDuckGo HTML） | `python scripts/web_search.py "<关键词>"` | 按需 |
| 抓取网页正文 | `scripts/page_fetch.py` | 按 URL 抓正文、去标签成纯文本 | `python scripts/page_fetch.py <url>` | 按需 |
| 查本地知识库历史档案 | `scripts/kb_query.py` | 按关键词检索决策/评测/案例档案（关键词打分） | `python scripts/kb_query.py <关键词>` | 按需 |
| 吸收写作规矩/模板 | `scripts/ingest_template.py` | 模板吸收（compress/extract），把写作规矩进知识库或提炼成指引（不调 LLM） | `python scripts/ingest_template.py ...` | 按需 |
| 领域知识库入库 | `scripts/rag_ingest.py` | 概念层 Markdown / 论文层 JSON → ChromaDB（逐篇嵌入，慢） | `python scripts/rag_ingest.py ...` | **周期性，非每循环** |
| 领域知识库检索 | `scripts/rag_query.py` | 分层加权混合检索（向量召回 + 关键词分），`--json` 出结构化 | `python scripts/rag_query.py "<问题>"` | 按需（流水线第 0 段 `kb_lookup` 走库内接口，同源） |

**调用纪律**：跑模型/联网前先看时间与峰谷铁律；入库类脚本只在语料更新时跑，不做每循环动作。

## 三、外置包位置约定

- 根目录：`工具与参考/Agent外置工具包/`，下按用途建中文包：
  - `演示工具包/`：产物能力外置（PPT/图表/流程图/网页幻灯片）；
  - `AI评测工具包/`：执行器外置（Promptfoo）。
- 包内统一结构：`skills\`（技能文件夹，每个含 SKILL.md；Pi 启动时经 `scripts/run-pi.ps1` 的 `--skill` 参数加载已装项）、`tools\`（运行依赖：venv、node 环境等）、`工具包说明.md`（装箱单：清单、来源、license、更新方式）。
- 新增工具包在 `工具与参考/Agent外置工具包/` 下另建中文文件夹，并在本表增节登记；登记时注明属于"产物能力"还是"执行器"外置。

## 五、双向维护约定（路径变更必读）

- 本文件是"导向文件"：第二节、二·补登记的每个技能、第四节登记的项目内技能，都能从这里找到实体位置。
