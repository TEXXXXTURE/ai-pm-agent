# 外置工具路由表（Agent 查工具先查这里）

> PM Agent 遇到**非 Markdown 产物**需求（做演示/画图/做 PPT/做网页）或需要**通用执行器**（批量模型评测）时，先查本表：
> ①该形态有没有对应工具；②工具装没装；③装了去哪调用，没装怎么获取。
> 外置分两类（workflow-design.md v3.0 原则 4）：**产物能力外置**（演示工具包，Agent 本体做不了的产物）与**执行器外置**（AI 评测工具包，无状态机械执行器；工作流主干在 `src/`）。
> 工具实体在项目内：`工具与参考/Agent外置工具包/`（各包装箱单见包内 `工具包说明.md`），该目录由 .gitignore 排除不进 git。
> 建立：2026-09-10（S018，T5-1）；2026-09-12（S028）随用户迁入项目内；2026-09-12（S031 块1）新增 AI 评测工具包节。 <!-- [MA 2026-09-12] -->

## 一、使用规则（给 Agent）

1. **先判形态**：用户要的是文档（PRD/报告/纪要 → Markdown，你自己做）还是**演示物**（PPT/网页幻灯片/数据图表/流程图/泳道图/思维导图/视频）？演示物不走 Markdown，走本表。
2. **先出交接单再动手**：演示需求先按 `demo-handover` 技能澄清五要素（演示什么/受众/核心结论/数据素材/期望形式），信息不全先问。
3. **查表定位**：按"期望形式"找到对应工具行，看**安装状态**：
   - **✅ 已装**：按"调用入口"加载技能、按技能指引制作；产物落 `output/`。
   - **⏳ 未装/待配环境**：明确告诉用户"该工具尚未就绪"，给出两个选择——**①用户自行提供工具**（放进外置包 skills/tools 并通知登记）；**②授权 Agent 下载本表已预筛选的工具**（说明来源、用途、安装方式，经用户同意后执行，装完更新本表状态）。
4. **不许假装能做**：没有对应工具时，不得硬用 Markdown 拼凑演示物，也不得编造工具调用结果；诚实说明能力边界（G8）。
5. **用完登记**：新装/更新工具后，更新本表与外置包 `工具包说明.md` 的状态。

## 三、外置包位置约定

- 根目录：`工具与参考/Agent外置工具包/`，下按用途建中文包：
  - `演示工具包/`：产物能力外置（PPT/图表/流程图/网页幻灯片）；
  - `AI评测工具包/`：执行器外置（Promptfoo）。
- 包内统一结构：`skills\`（技能文件夹，每个含 SKILL.md；Pi 启动时经 `scripts/run-pi.ps1` 的 `--skill` 参数加载已装项）、`tools\`（运行依赖：venv、node 环境等）、`工具包说明.md`（装箱单：清单、来源、license、更新方式）。
- 新增工具包在 `工具与参考/Agent外置工具包/` 下另建中文文件夹，并在本表增节登记；登记时注明属于"产物能力"还是"执行器"外置。

## 五、双向维护约定（路径变更必读）

- 本文件是"导向文件"：第二节、二·补登记的每个技能、第四节登记的项目内技能，都能从这里找到实体位置。
- **反向回指**：项目自有技能文件（demo-handover、humanize-writing、diagram-mermaid、ai-eval 薄技能）头部标有"登记于本路由"，从实体也能找回本文件。
- 第三方克隆技能（frontend-slides、lieflat-charts、ppt-master）文件内**不加标记**（升级会被覆盖），与本表为单向关系，靠本表维护。
- **路径变更固定动作**：①全项目搜索旧路径列出全部牵扯文件；②逐个改（代码路径集中到一个变量定义）；③改完再全项目搜索，旧路径归零（历史会话骨架除外）；④同步更新本约定与 run-pi.ps1。 <!-- [MA 2026-09-12] S028 -->
