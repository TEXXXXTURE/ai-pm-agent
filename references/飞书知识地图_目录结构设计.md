# 飞书知识地图 — 目录结构设计

> 本文档定义飞书知识地图的完整目录结构，以及与外部 RAG 知识库的对应关系。
> 定位：飞书是知识地图（人读导航 + Agent 路由），不是内容源。
> 对应选型文档：《AI Agent 知识库 RAG 选型笔记》选型一、选型八

---

## 一、设计原则

### 1.1 飞书的两个核心功能

1. **人主动学习的入口**：在飞书里看知识体系、读笔记、标注判断，需要深度内容时跳转到 RAG 库原文
2. **Agent 检索的导航层**：Agent 先读飞书地图定位领域和分类，再定向到 RAG 库做深度检索

### 1.2 结构对齐原则

飞书的分级标题与外部 RAG 库的目录结构**一一对应**：

| 飞书层级 | 外部 KB 层级 | 说明 |
|---------|-------------|------|
| 一级标题（知识大类） | 顶层目录 | 如「一、基础概念」→ `concepts/` |
| 二级标题（知识点） | 单篇文档 | 如「1.1 Agent 是什么」→ `agent-definition.md` |
| 三级及以下标题 | 文档内小节 | section-aware 分块的 chunk 边界 |

### 1.3 每个飞书知识点包含什么

每篇飞书文档（对应一个二级标题）包含三部分：

1. **简要说明**（1-2 段）—— 一句话概括这个知识点，加上最核心的 2-3 个要点
2. **我的笔记** —— 自己的理解、判断、标注、与其他知识点的关联（飞书最有价值的部分，外部任何知识库替代不了）
3. **KB 路由** —— 指向 RAG 库里对应条目的 ID 和链接，供 Agent 定向检索

## 二、完整目录结构

### 一、基础概念与分类

> 回答"是什么、怎么分类、有什么区别"的问题。
> 对应 RAG 库：concept 层的 concepts/ 目录

```
一、基础概念与分类
  1.1 Agent 是什么
      - 定义：能感知环境、做决策、采取行动的智能体
      - 核心要素：感知 → 推理 → 行动 → 反馈
      - 与普通程序的区别：有自主性、能应对不确定性
      - KB 路由：concept/concepts/agent-definition

  1.2 Agent vs Workflow
      - 核心区别：谁决定下一步（模型 vs 代码）
      - Workflow 的优势：确定性、可审计、低成本
      - Agent 的优势：灵活性、应对开放问题
      - 选择判据：问题空间的分支变异速度是否超过代码枚举能力
      - KB 路由：concept/concepts/agent-vs-workflow

  1.3 主流分类体系对比
      - 1.3.1 Andrew Ng 四模式（Reflection / Tool Use / Planning / Multi-Agent）
      - 1.3.2 Anthropic Workflows vs Agents + 五种模式
      - 1.3.3 Lilian Weng 组件视角（规划/记忆/工具）
      - 1.3.4 社区"四级阶梯"的真相（教程圈拼接叙事）
      - KB 路由：concept/concepts/classification-systems

  1.4 按自主程度的分类轴
      - 从"工具调用"到"全自主"的连续谱
      - 各阶段的典型特征和适用场景
      - 我们的位置：Workflow + 节点内有限自主
      - KB 路由：concept/concepts/autonomy-spectrum

  1.5 核心范式演进
      - CoT → ReAct → ReWOO → Plan-and-Solve → ...
      - 每条范式的提出背景、核心思想、适用场景
      - 不要理解成"进化链"，而是不同思路的探索
      - KB 路由：concept/concepts/paradigm-evolution
```

## 三、与 RAG 库的对应关系总表

| 飞书一级标题 | RAG 库顶层目录 | 知识层 | 权重 |
|-------------|---------------|--------|------|
| 一、基础概念与分类 | concepts/ | concept | ×2.0 |
| 二、架构与核心模式 | architecture/ | concept | ×2.0 |
| 三、框架与平台 | frameworks/ | concept | ×2.0 |
| 四、应用与场景 | applications/ | concept | ×2.0 |
| （各分类下的论文） | papers/<category>/ | curated-paper / tracked-paper | ×1.5 / ×1.0 |
| 五、项目内部文档 | （无，纯飞书内容） | — | — |

### 论文在知识地图中的位置

精选论文和追踪论文**不单独列一级标题**，而是挂在对应知识点下面作为延伸阅读。

示例：
```
二、架构与核心模式
  2.1 规划与推理
      ...（概念说明）...
      📚 经典论文
        - ReAct: Synergizing Reasoning and Acting（Yao et al. 2022）
        - Plan-and-Solve Prompting（Wang et al. 2023）
        - ...
```

每篇论文在飞书里有一行简介 + 链接（指向 RAG 库中的论文详情），但完整 abstract 和正文在 RAG 库里。

## 四、实施路径

### 阶段一：骨架搭建（第 1 周）

1. 在飞书创建知识库「AI Agent 知识地图」
2. 创建 5 个一级页面（对应五大类）
3. 每个一级页面下创建 3-5 个二级页面（核心知识点）
4. **先不填内容，只搭结构**，确保整体框架正确

### 阶段二：核心内容填充（第 2-3 周）

1. 优先填充「一、基础概念与分类」和「二、架构与核心模式」
2. 每个知识点写简要说明 + 我的笔记
3. KB 路由先留占位，等 RAG 库建好后回填
4. 同步把对应的概念文档导入 RAG 库

### 阶段三：扩展与迭代（持续）

1. 逐步补充「三、框架与平台」「四、应用与场景」
2. 在各知识点下添加精选论文索引
3. 根据学习和使用情况，持续更新「我的笔记」

## 五、命名与格式规范

### 5.1 页面命名

- 一级页面：`一、XXX`（中文数字 + 顿号 + 名称）
- 二级页面：`1.1 XXX`（数字编号 + 空格 + 名称）
- 三级页面：`1.1.1 XXX`

### 5.2 KB 路由格式

每篇飞书文档末尾统一格式：

```
---

📎 KB 路由
- RAG 库 ID: concept/architecture/planning
- 对应文档: planning.md
- 上次同步: 2026-09-12
```

### 5.3 笔记格式

「我的笔记」部分用高亮块（飞书的高亮/引用格式），与正式内容区分：

```
💡 我的理解
- ReAct 的核心贡献不是"推理+行动"这个想法本身，而是证明了
  把推理过程写出来（verbalization）能显著提升工具调用的准确性
- 这里的"Reasoning"更像是"自言自语"，不是严格的逻辑推理
```
