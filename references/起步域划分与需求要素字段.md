# 起步域划分与需求要素字段（2026-10-16 定稿）

> 依据：选型笔记第二轮定调（多域库网格）+ 交接遗留两项（起步域待认、需求要素字段待议）。按「建议定稿、不同意再改」处理，实施随架构骨架阶段落地。

## 一、起步域划分（5 域，一级嵌套封顶，库数 10-12）

| 域 | 代号 | 收什么 | 子库示例（一级嵌套） |
|---|---|---|---|
| AI 与 Agent | `ai` | 范式/模型/Agent 架构/记忆/规划/RAG/评测 | concepts / frameworks / platforms / rag |
| 代码与工程 | `code` | 编码方式、工程实践、调试、测试、DevOps | coding / testing / devops |
| 泛化方法 | `methods` | 产品方法论、需求分析、项目管理、分析框架 | product / research / pm |
| 硬件 | `hardware` | 单片机、嵌入式、传感器、硬件选型 | embedded / sensors |
| IT 与 PC | `it-pc` | 系统、软件、网络、办公工具常识 | systems / tools |

- 域的判定词表先用「域名 + 关键词」起步（后续可 LLM 分类），查询经路由进目标域库，无果逐级降级（其他域 → 信源梯度外扩）。
- 现有 5655 chunk 全部归 `ai`（语料本就是 AI 领域）；新域随「搜罗→整理→切片」循环逐个建。
- 单域「总结完毕」即冻结**索引形态**（不硬叠切片），但可低频「整理→重切」（五轮定调）。

## 二、需求要素 → 元数据过滤字段（内容侧口径）

旧议「成本量级/合规敏感度」是需求侧字段，打在知识内容上说不通。定为**内容侧五字段**，入库前由 Agent 按规则打标、人只审（归入库前清洗环节）：

| 字段 | 取值 | 用途 |
|---|---|---|
| `domain` | ai / code / methods / hardware / it-pc | 路由进哪个域库（已随分库实现） |
| `module` | 域内子库名 | 域内定向过滤 |
| `scenario` | 适用场景标签（如选型/排障/设计/评审） | 「什么场合用得上」的过滤维度 |
| `constraint` | 约束标签（如成本敏感/合规/实时性/离线） | 对齐需求侧约束的桥——内容声明「我适用于什么约束环境」 |
| `deliverable_type` | 交付物类型（PRD/工单/评测/发布计划/代码/报告） | 「产出什么时参考」的过滤维度 |

- 需求要素转元数据过滤（检索叠加层）：把用户需求里的约束/场景/交付物翻成上述过滤条件，缩小召回面。
- 同构要求：跨库元数据必须同构（字段名与取值口径全库一致），子库切法可不同。
- 实施位置：入库前打标（Agent 按规则）+ store 检索的 where 过滤；随架构骨架阶段一起上。
