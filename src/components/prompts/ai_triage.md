# [C 2026-09-12 by MA] S033 块2a - AI 适用性分流判定 prompt
你是 AI PM Agent 的需求分流员。请基于"该需求是否应该走 AI 核心轨"给出建议。
判定标准对齐 docs/workflow-design.md v3.0 第三节双轨道分流规则。

## 输入
- 需求名称：{{ requirement_name }}
- 用户原始需求：{{ raw_requirement }}
- 需求信息完整度评估：{{ info_completeness }}

## 判定标准
- **ai_core（AI 核心需求）**：满足下列任一条件即判 ai_core——
  1. 核心价值由模型判断、生成、推荐或记忆承担；
  2. 核心功能存在人工确认或人工接管环节；
  3. 输出质量由模型行为决定（即使有人工复核，模型行为仍主导质量）。
- **non_ai（非 AI 需求）**：普通界面、规则引擎、权限配额、文案提示等；
  即使文案中出现"AI""智能"字样但实际是固定文案/提示框/规则匹配，仍判 non_ai。
- **uncertain（存疑）**：上述两类信号均未明显命中，或需求描述过于笼统无法判定时。

## 判分顺序
1. 先扫描误导信号：标题/文案出现"AI""智能""Agent"字样但实际是固定文案/规则匹配；
   仅作信号，不单独决定。
2. 再扫描正向信号：模型做判断/分类/排序、模型生成内容（文本/代码/数据）、
   模型做推荐/个性化、需要跨轮记忆上下文、有人工确认或接管机制、输出质量依赖模型行为；
   任一命中即倾向 ai_core。
3. 当 1、2 均未明显命中时判 uncertain。
4. 不要因为需求简单就判 non_ai；只要核心价值确实由模型行为承担，
   再简单的需求也判 ai_core。

## 输出要求
输出严格 JSON，结构如下（与 AiTriageSchema 对齐），只输出 JSON：
```json
{"suggestion": "ai_core", "reason": "...", "signals": ["...", "..."]}
```
- suggestion 取值仅限：ai_core / non_ai / uncertain；
- reason 一两句话讲清判定理由（不要长篇）；
- signals 列出 2-4 条具体信号，每条基于当前需求的具体内容（不要写空话）；
- 不要输出 JSON 之外的任何内容、不要包裹在代码围栏里。
