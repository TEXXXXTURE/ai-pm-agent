# AI 测评工具拆解：形态、实现机制、许可证与复刻范围

本文是 AI 评测的学习文档。结论先行：**核心没有秘密算法，护城河是云服务、生态绑定和覆盖量的体力活。**

## 一、工具的四种产品形态

| 形态 | 代表 | 利 | 弊 |
|---|---|---|---|
| 命令行 + 声明式配置 | promptfoo、lm-eval-harness | 不写代码、接 CI、换模型改配置 | 复杂多步过程表达不了 |
| 代码库/测试框架 | DeepEval、Ragas、Giskard、Inspect | 能测复杂过程、自定义判分、与代码一体 | 要写 Python |
| 跑分编排框架 | OpenCompass、HELM | 批量基准、模型对比 | 只覆盖模型评测 |
| 观测平台（带服务端） | Langfuse、LangSmith、Phoenix、Opik、Braintrust | 线上监测、协作、版本 | 要部署服务、绑生态 |

没有任何单一工具同时覆盖「模型评测」与「业务评测」两大阵营。

## 二、逐个工具拆解

### promptfoo（MIT，TypeScript）
- 资产不在算法：大量模型端点适配、30+ 断言、红队（13 个行业方向自动生成对抗题）、本地网页界面。
- 断言里 equals/contains/regex/json/bleu/levenshtein/latency/cost 为硬算；factuality/context-faithfulness/geval/llm-rubric 为「提示词+模型判定」。
- 定位：内容输出评测主力、回归题定期重跑、红队对抗。

### DeepEval（Apache-2.0，Python）
- 挂 pytest，40+ 指标目录结构统一：`指标.py + schema.py + templates/`，差异主要是提示词。
- 指标含 faithful/hallucination/answer-relevancy/G-Eval/agent goal/tool/MCP/PII/bias 等；另带考题合成器、优化器、红队、模拟器。
- 定位：语义断言、agent 指标。

### Ragas（Apache-2.0，Python）
- 专攻 RAG。忠实度是两段提示词流程：先把答案拆成原子陈述（去代词），再逐句对照上下文判真假。
- 指标：忠实度、上下文精确率/召回率、回答相关性/正确性、工具调用准确率/F1、噪声敏感性、SQL 语义等价等。

### Inspect（MIT，Python，英国 AISI）
- 抽象最干净：`eval / solver / scorer / dataset / tool` 五件组合出任意评测，带 log 和 viewer。
- 定位：自建评测工具内核的首选参考。

### lm-evaluation-harness（MIT，Python）
- 资产是 1000+ 基准任务的 YAML 定义与统一执行。模型公开基准跑分直接调用，不必重写。

### OpenCompass / HELM（均 Apache-2.0）
- 多基准批量编排与标准化口径，只覆盖模型评测阵营。

### Giskard（Apache-2.0，Python）
- 扫描器 + 对抗题生成，覆盖幻觉/注入/偏见；企业版闭源。

### Arize Phoenix（**Elastic License 2.0**）
- phoenix-client / phoenix-evals / phoenix-otel / sqlean 组成，OpenTelemetry 追踪 + 本地评测。
- ELv2 限制：**可改自用，不能提供托管服务，不能提供其付费管理功能**；不可混入 MIT/Apache 代码。

### Langfuse（MIT 主体 + **ee/ 商业许可**）
- ClickHouse + Postgres + worker 架构；ee/ 目录（SSO、审批、高级评估）不可碰。
- 线上平台能力强；无服务端条件下不适用。

### 闭源商业平台（仅 SDK 开源）
- LangSmith（SDK MIT）、Confident AI、Braintrust（SDK Apache）：核心是「存调用记录→网页看→跑评测→管版本→标注队列」，无算法秘密，是数据库+网页工程量。

## 三、复刻可行性汇总

| 工具 | 许可证 | 可复刻 | 限制 |
|---|---|---|---|
| promptfoo | MIT | 全部思路 | TS 代码需用 Python 重写；大量模型适配不值得逐个做 |
| DeepEval | Apache-2.0 | 全部指标模板 | 保留版权声明 |
| Ragas | Apache-2.0 | 全部流程 | 同上 |
| Inspect | MIT | 五件抽象 | 无 |
| lm-eval-harness | MIT | 直接当跑分内核调用 | 不必重写 |
| OpenCompass/HELM | Apache-2.0 | 编排思路 | 只覆盖模型评测 |
| Phoenix | ELv2 | 只学架构 | 不能托管、不能混许可证 |
| Langfuse | MIT + ee | 主架构可参考 | ee/ 不碰 |
| Giskard | Apache-2.0 | 核心扫描器 | 企业版闭源 |
| LangSmith/Confident/Braintrust | 闭源 | 只还原概念 | 看不到源码 |

## 四、实现机制的本质

语义类指标统一模式：**精心写的提示词 → 要求模型按 JSON schema 输出判定 → 代码解析聚合成分**。传统类指标（正则、BLEU、ROUGE、编辑距离、延迟、费用）是普通工程。复刻难度低，成本是逐个移植指标模板的体力活。可做得更好的方向：① Inspect 骨架 + DeepEval/Ragas 指标 + promptfoo 红队合一；② 统一覆盖模型与业务两大阵营；③ 中文判分口径（现有模板为英文设计）。

## 五、自建路线（按需，不提前造轮）

1. 先用通用评测技能调度现有工具，每次调用记入调用登记。
2. 同一路径走过两次以上且验证可用 → 固化；现有工具满足不了 → 启动自建。
3. 自建顺序：Inspect 五件为内核 → 公开基准直接调 lm-eval-harness → 业务指标按 Apache 许可移植 DeepEval/Ragas 模板（保留归属）→ 红队与断言参考 promptfoo 用 Python 重写（不复制代码）→ Phoenix/Langfuse 只学架构。
4. 自建工具以 Apache-2.0 发布，与上述许可证兼容。
