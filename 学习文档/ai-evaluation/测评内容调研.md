# AI 测评内容调研：题从哪来、能测出什么、局限在哪

本文是 AI 评测的学习文档，不评工具，只评**测评本身的有效性**：每类题怎么产生、用什么规则判分、能测出什么数据、在什么情况下测不出。判断一个测评能不能用，依次看四件事——题的来源、筛题规则、判分单位、已知局限。

## 总判断

| 问题 | 结论 |
|---|---|
| 有没有一个测评能回答「这个 AI 好不好」 | 没有。每个 benchmark 只测一个特定对象，分数跨对象不可比较 |
| benchmark 高分能否推出业务可用 | 不能。HLE/MMLU-Pro/AIME 测的是脱离产品的能力上限，与业务成功率无直接换算 |
| 测评会不会失效 | 会，且普遍：基准饱和、题被训练数据污染、出题人盲区、模型裁判偏向 |
| 选型的正确动作 | 先写清要测的具体行为，再找测同一对象的测评；不反向用 benchmark 凑结论 |

## 一、模型能力测评

### HLE（Humanity's Last Exam，2025-01，Nature 2025 发表）
- **题的来历**：全球各学科的学者和从业者原创，不是从教材题库抓取。共 2,700 题（含约 300 道多模态），覆盖数学、人文、自然科学、法律、历史、心理、哲学等。
- **筛题规则（核心机制）**：每题提交前先用当时最强模型实测——**模型能答对的题直接拒收**；再经两轮人工评审（研究生评审给反馈、组织者和专家终审）。评审口径：一般要求研究生/博士难度，但「题不难、只是模型答不出」的题也收。
- **判分单位**：选择题或短答案，答案必须唯一、无歧义、可机器核验，且不能靠快速检索得到。
- **能测出什么**：模型与「人类专家闭卷学术能力」的差距；分数低是设计出来的。
- **局限**：
  - 只测闭卷、有唯一答案的学术问题，开放任务、真实工作场景完全测不了；
  - 模型非零得分里有噪声（选择题猜对、推理时好时坏），出题方选择保留；
  - 随模型变强同样会饱和，只是时间问题。

### MMLU-Pro（2024-06）
- **题的来历**：在原 MMLU（57 学科考试题）基础上改造，剔除简单题，并从 TheoremQA、SciBench、STEM 题库网站补充推理类题，共约 12,000 题。
- **筛题规则**：用模型过滤掉「琐碎、有噪声」的题（该工序删去 5,886 题）；选项从 4 个扩到 **10 个**，干扰项由模型生成并人工核验，把随机猜对率从 25% 压到 10%；删除图像题和答案无法完整提取的题。
- **判分单位**：十选一；标准跑法是 5-shot 带思维链，按最终选项判分。
- **能测出什么**：跨学科的推理与知识水平，比 MMLU 抗猜、抗刷；论文给出的错误类型分布（推理错 39%、缺特定知识 35%、计算错 12%）可用于定位短板。
- **局限**：
  - 前身 MMLU 已饱和（GPT-4 之后长期停在 86–87%），MMLU-Pro 是续命而非新对象；
  - 分数对提示词和判分方式敏感，榜单排序会因此变化；
  - 仍是考试题形态，不涉及工具、流程和真实环境。

### AIME（美国数学邀请赛，直接用作 benchmark）
- **题的来历**：真实竞赛原题，每年一套 15 题，答案为 0–999 的整数，无部分分。
- **判分单位**：整数精确匹配，常用多次采样（pass@k / cons@k）。
- **能测出什么**：多步严格数学推理，判分零主观。
- **局限（已被实证）**：**AIME 已严重饱和/污染**——新出的原创竞赛题集（AMO-Bench，50 道 IMO 级新题）上最强模型从 AIME 的 90%+ 跌到 52.4%。即「AIME 高分」很大一部分来自题被见过，不代表当前真实数学能力。RLVR（可验证奖励强化学习）的部分头条增益也被指出混有评测预算不一致等干扰。

### SWE-bench（2023-10，ICLR 2024）
- **题的来历**：真实 GitHub 仓库的 issue + 对应已合并的修复。模型拿到仓库和 issue，要产出补丁；用修复当时引入的测试（FAIL_TO_PASS）和原有测试（PASS_TO_PASS）判分。
- **筛题规则**：从高质量流行 Python 仓库中筛，要求 issue 描述清楚、补丁有测试可验。SWE-bench Verified（与 OpenAI 共建，人工核验 500 题）解决原集里描述不清、测试不可靠的问题。
- **判分单位**：补丁应用后跑测试，结果二元。
- **能测出什么**：定位真实代码库、改代码并通过真实测试的端到端能力，这是最接近工程现场的模型/Agent 交界测评。
- **局限**：任务耗时耗钱（每题要起环境装依赖）；原集噪声导致分数被质疑；只能测有测试覆盖的修复类型。

## 二、Agent 与流程测评

### τ-bench（tau-bench，2024-06）
- **题的来历**：人工先设计真实业务的数据库 schema、API 和业务政策（零售：1,000 用户、1,000 订单；航空：500 用户、300 航班、2,000 预订），再由模型生成任务，人工筛至 **零售 115 题、航空 50 题**。
- **测的过程**：agent 与「模型扮演的用户」多轮对话，只能通过给定 API 工具操作数据库。
- **判分单位（独到之处）**：不看对话文本，直接比对**对话结束后的数据库状态**与人工标注的目标状态；另提出 **pass^k**：同题多次独立试验全部成功才算过，用来测可靠性而不是单次运气。
- **能测出什么**：多轮信息收集、政策遵守、工具操作、错误纠正的综合过程。论文发表时 GPT-4o 成功率不足 50%。
- **局限**：模拟用户与真实用户有差距；只有两个领域；环境是受控数据库，覆盖不了开放式工具链。

### 通用判据
测 agent 必须逐段拆出：任务成功率（结果）、工具选择准确率、参数正确率、轨迹（过程是否合理）、错误恢复。一个总分无法定位问题。终端类 agent 基准（如 TUA-Bench）显示最强者也只有 65.8%，短板集中在长程规划和执行监控。

## 三、内容输出与 RAG 测评

- **判分分三档**（按答案确定性）：
  1. 有唯一答案 → 硬规则（等于/包含/正则/JSON 字段）；
  2. 有明确对错但表述开放 → 评分规则：事先列必命中的事实点和不许出现的错误，按点给分；
  3. 无标准答案 → 事先写死多档 rubric，或模型交叉评。
- **RAG 专项（Ragas 口径）**：忠实度用两段式——先把答案拆成无代词的原子陈述，再逐句对照检索上下文判真假；另测上下文精确率/召回率（检索段）和回答相关性。拆成两段才能分清是检索错还是生成错。
- **合成数据的问题**：Ragas 等支持从文档自动生成合成考题，但有专门研究《Can we Evaluate RAGs with Synthetic Data?》追问其代表性——**合成题上的得分能否外推到真实用户问题，仍需用真实问答样本校准**，不能只报合成分。
- **未解决的行业难题**：模型裁判有偏向（偏好长答案、偏好某种措辞、位置偏向）、出题人有盲区、用户答案分布会变。语义判分的客观性没有彻底解法，只能靠：判据事先写死、裁判与被测模型不同源、人工抽检。

## 四、关于「分数本身可不可信」

| 威胁 | 含义 | 实证 |
|---|---|---|
| 数据污染 | 题或答案进入训练集 | AIME 新题集分数骤降即为证据 |
| 基准饱和 | 强模型全部接近上限，失去区分度 | MMLU 长期停在 86–87% |
| 评测敏感性 | 换提示词/判分规则，排名就变 | MMLU 已知问题 |
| 指标口径混淆 | 把「尝试次数/采样预算」差异当成能力差异 | RLVR 评测被点名的干扰项 |

元指标包括：pass@k（至少一次成功）、cons@k（多次一致）、Elo（对战）、LLM-as-judge 及其校准。

## 五、引用 benchmark 的规则

1. 先写清要测的**具体行为和失败形态**，再按对象选测评；禁止先选工具再解释。
2. benchmark 只回答「同类闭卷题上的相对位置」，不回答「业务能不能上线」。
3. 引用 benchmark 分数时必须同时报：发布/出题日期、判分口径（shot 数、pass@k）、是否有污染/饱和警示。
4. 涉及语义判分，判据必须先于跑批写死；模型裁判结果标「需人工抽检」。
