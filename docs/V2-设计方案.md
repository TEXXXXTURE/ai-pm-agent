# V2 设计方案

> 这个项目的下一版。V1 已经做完，放在 `main` 分支上；V2 目前只做到设计，还没有动手实现。

## 一、要做什么

V2 不推倒重来，在 V1 上继续改。整条主线一句话：**AI 产品经理的每一项职能，都在流水线上占一步，配一个外置工具。**

流水线走到哪一步，就把上一步的产出交给那一步的工具；工具做完，把结果数据交回来。工具自己在外面升级演进，流水线不关心它内部怎么做，只收结果。

这是 V1 那个分法的继续：流水线保稳定，常驻对话 Agent 保灵活，外置工具让能力可以一直长。

## 二、能力怎么加进来

1. 先把还没做完的职能清理出来
2. 一次挑一个，单独写成一份需求
3. 按需求设计对应的工具；动手之前先过下面的尺子
4. 工具做出来，在外置工具路由表上登记一行；流水线走到那一步就调它

## 三、尺子：一件事该放进流水线，还是放到外面

| 判据 | 怎么问 | 命中往哪走 |
|---|---|---|
| 市场上有没有成熟方案（最重要） | 外面有没有现成好用的 | 有 → 放外面 |
| 放进流水线有多难做 | 在流水线里做它特别费劲吗 | 费劲 → 放外面 |
| 放进流水线有没有成长空间 | 流水线给不给得了它继续变好的余地 | 给不了 → 放外面 |
| 是出结论还是干活 | 是算「过没过、推不推荐、要不要停」，还是要真的跑一个动作 | 出结论留在流水线，干活放外面 |

还有一条：不只是不常用的才放外面。**重要的内容，如果放在流水线里做不出高水平，也要放外面。**

## 四、已经定下来要放外面的

| 要做的事 | 为什么放外面 |
|---|---|
| 画原型 | 流水线只能出文字描述，做不出能点的原型；外面现成方案多 |
| 画流程图、信息架构、结构图 | mermaid 已经装好；流水线只产出「要画什么」的文字 |
| 模型评估、评测跑分 | Promptfoo 已经装好，但只用了一半——出考题配置、读报告还写在流水线里，要挪出去 |
| 数据底座测试 | 外面有成熟的数据质量检测；流水线只收「这个底座能不能用」的结论 |
| 交付物排版美化 | 任何阶段的产物最后都用得上（Pandoc、演示工具包已经装好） |

## 五、留在流水线里自己做的

「出结论」那一类留在代码里硬算，图的是确定、可复现、前后一致：需求走哪条轨、及格线过没过、要不要停下来等人、评审过不过、推荐哪个方案。

这些不交给工具。

## 六、一条硬要求：能拆开

每一项职能都要能单独用、单独换、单独测，不绑死在整条链上。这决定「流水线能不能单独调用某一项职能」，是后面所有功能设计的基础。

## 七、整体结构

```
AI 产品经理工作流
├─ 流水线（主骨架）：想法 → 需求分析 → 方案设计 → 评审 → 评测 → 发布计划
│    每一段只做四件事：走到这步、把上一步产出交给工具、收工具的结果、判定
├─ 常驻对话 Agent：轻活直接做，重活送进流水线
├─ 外置工具（可以一直长）：按职能装在流水线外面，按段调用，只传数据进出
│    ├─ 已有：评测、演示、图表
│    └─ V2 要加：模型评估、数据底座测试、其他 AI PM 职能
└─ 知识与规则：参考库、知识库、提示词、规则（改文件即改）
```

## 八、还没做的职能

| 阶段 | 缺什么 | 大概念挂在哪 |
|---|---|---|
| 需求分析 | 六格已经定稿，代码还没动（查家底 / 记录、体检、AI 预期、隐私合规成本 / 确认走哪条轨 / 按意见重出并逐条对照 / 深挖 / 评估数据底座） | 主体在流水线，数据底座评估可以放外面 |
| 需求拆解 | 数据底座评估怎么落地；量化指标放在哪（候选模型池已经前置，评测体系设计仍在 PRD 之后） | 判定留流水线，数据底座测试放外面 |
| 产品方案设计 | 业务流程、信息架构、原型、功能规则、异常场景、交互逻辑、输入输出、权限、边界，要能做成一套可以分发的方案 | 判定留流水线，原型和图表类放外面 |
| 多方评审 | 算法、数据、安全三种角色的评审；一票否决怎么定还没定 | 流水线（判定） |
| 开发落地跟进 | 落地跟进、提示词和模型变更的管控、推理成本监控 | 二期 |
| 再往后 | 灰度监控、数据飞轮 | 二期 |
